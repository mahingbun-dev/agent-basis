## 1. 一句话目标

在 agent-basis 仓库按「**官方 DSH 内核 + profile 裁剪组合 + 企业插件层**」路线（下称路线③）交付第一个企业场景——**工业分析领域包最小集**（对齐图纸《智能体平台分层架构》：时序查询/知识问答/预警研判/报告生成主链路），验收 = 工业包金集 replay 全过 + ai-evo 平台门禁 passed + Web 档（裁切组合）boot+smoke 通过（嵌入档二阶段交付）。

## 2. 背景与路线定案

**决策问题**：企业 agent 应「直接用 cordis 核心从零开发」还是「基于成熟 deepseek-harness（DSH）做插件」？评判标准：稳定、高效、高性能。

**本次核实的关键事实**（非记忆，两仓直接验证）：

1. DSH 中的 cordis 是 deepseek-ai 自维护 fork（`@deepseek-ai/cordis` 4.1.0，见 `deepseek-harness/vendor/cordis/package.json`）——不存在「中立 cordis 内核」可投靠；走 cordis 路线 = 依赖 deepseek-ai 的 fork 却放弃其全部上层资产。
2. DSH 上层约 50 个包覆盖 session 持久化/checkpoint、compaction、shell/PTY、sandbox、MCP、guard、credentials、web client（`deepseek-harness/packages/`）——从零自建 = 亲手重写这张硬骨头清单。
3. profile/patch 是官方组合机制：patch 可 replace/insert 行，sdk-minimal profile 是「最小组合」官方先例（见 `basis/basis-minimal/README.md`）。**全量宿主与极简内核是同一个 npm 包的两种启动组合，不是两个产品。**
4. agent-basis 已有两条路线的实证资产：插件层 12 包 / 776 测试 / 评测门禁（宿主路线）；`basis/` 极简原型 + 自研 OpenAI 适配器 + npm 启动器组合（`scripts/init-profile.mjs`，最小组合路线）。

**三路线评判**：

| | ① fork cordis 从零自建 | ② DSH 全量宿主 + 插件 | ③ DSH 内核 + profile 裁剪 + 插件（定案） |
|---|---|---|---|
| 稳定 | ✗ 硬骨头全自研成 bug 面 | ✓ 上游维护；seam 编译期钉住；门禁兜升级 | ✓ 同②，且审计面最小（telemetry/credentials 可裁） |
| 高效 | ✗ 首月产出轮子非企业价值 | ✓ 已被 12 包插件层交付实证 | ✓ 同②，多一次性组合模型学习成本 |
| 高性能 | △ 名义瘦、实际输在手搓 IO | △ prompt 注入面大，靠守护插件补救 | ✓ 组合面最小 = prompt 前缀最稳 = KV-cache 命中率最高 |

**定案**：路线③为主形态；①不作为企业主路线（单人团队维护负债不可接受）。性能胜负手在组合面与 KV-cache，不在内核厚薄。

## 11. Web 档裁切清单（首期裁定）

### 11.1 裁切三原则

1. **合规/稳定优先**：凡外联第三方端点、自带凭据/账号体系、扩大审计面的行，首期一律裁。
2. **场景裁切**：首期（活动策划线）用不到的能力全裁——组合架构下每行都可一行 insert 回加，**裁是可逆的**。
3. **性能/成本**：裁 LLM 副调用、缩 prompt 注入面（每个工具行 = 一个进 system prompt 的 schema，模型选择分心随之减少）。
