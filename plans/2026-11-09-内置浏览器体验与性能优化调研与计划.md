## 0. 执行摘要

1. **本产品（eterna/agent-basis）模型侧目前没有任何浏览器工具**；DSH 内核的 browser-use 框架 + 三 provider **已公开发布到 npm（0.2.2-rc.1，与全树同版）**，但 dsh CLI 安装锚的依赖闭包不含它们，agent-basis 未装。启用是「装 2 个包 + profile patch insert 2 行，代码零改动」的事，但有三个前提：dsh-scope 单实例、模型图像能力路由、出站面合规（D1）。
2. **登录态持久的正解是 attach 模式接常驻 Chromium**：DSH playwright-mcp launch 模式硬编码 `--isolated`（内存 profile，Session 结束即弃），attach 模式（`--cdp-endpoint`）接外部常驻浏览器才能跨 Session 保登录。这与「服务端托管每用户常驻 Chromium」的架构互为因果。
3. **stagehand-native 对 eterna 是死路**：其 SDK 只认 OpenAI/Anthropic/Google/Groq/Cerebras 模型目录，README 明示不支持 DeepSeek 端点与 baseURL 覆盖；且 v4 的 act 缓存是 Browserbase 服务端缓存，本地浏览器明确无效。
4. **playwright-mcp 工具面已膨胀到 72 个**（默认 core 25 个；DSH 钉的 0.0.80 已落后，最新 0.0.84），且已并入 playwright-core 单体仓。72 工具对产品 agent 太重——**「收敛为自研精简工具面（ego-lite 风格 ~12 工具）」的必要性从"优化项"升级为"必然项"**。Playwright 官方自己也开始分流：编码 agent 改用 CLI+SKILLS，MCP 留给长程 agent 循环。
5. **a11y 快照 + ref 是业界收敛的感知路线**，Playwright 已把它从 MCP 专属上升为本体公开 API（`ariaSnapshot({mode:'ai'})` + `getByRef()` v1.64）。ego lite 实测：example.com 快照仅 1,179 字符（~300 tokens），HN 首页 34,707 字符（~8.7k tokens）——量化证明了快照通道的经济性。
6. **用户要的「快用三件套」（截图/正文/前端代码→会话）有现成挂点**：内核 `conversation` 服务已有 `send / sendSession / createDrafts（文件+图片附件草稿）/ setDraft / insertAsyncText`，M3 不需要发明新机制，只需给 ui-sidebar-browser 加导出动作。
7. **M4「两轨合一」的最省钱路径已被本 NAS 验证**：BrowserOS hosted Docker 就是「有头浏览器 + VNC(6080) + MCP(9010)」；本 NAS 现有 `chrome-novnc` 容器（noVNC 8104 端口）常驻运行。面板嵌入 noVNC 视图 + agent attach 同一浏览器 = 不用自研 screencast 管线。
8. **成功率要有现实预期**：HAL 验证的 Online-Mind2Web 榜首（SeeAct+GPT-5）仅 42.33%，厂商宣称的 97% 均非榜单成绩。产品设计必须内置人机协作（旁观/接管/求助），这也是 ego lite 和 BrowserOS 的共同选择。

## 2. 参照系深拆

### 2.1 ego lite（ego-browser CLI 0.6.2.9 / Chromium 156 / skill v2.2.0）【实测+文档】

**架构**：本机 CLI，agent 经 `ego-browser nodejs`（heredoc/-e 脚本，Node ESM）驱动一个真 Chromium。每次调用新 Node 进程，**TaskSpace/Page 标签（p1/p2）跨调用持久**，连续性边界在浏览器侧。刻意不暴露 Playwright（明确禁止 locator()/getByRole() 等），只给 TaskSpace/Page/mouse/keyboard/FileChooser 小面。

**准确性的来源**（机制 + 实测证据）：

| 机制 | 实测/原文证据 |
|---|---|
| TaskSpace 持久 + 永久页面标签 | 实测：spaceId=4，跨脚本 `taskSpace(7)` 复用；"Every invocation starts a new Node.js process. Task spaces, tabs, and Page labels persist" |
| snapshot-first + ref | `snapshot()` 返回带 ref 的 a11y 树；`{scope:"full_page"}` / `{scope:"subtree", root:"@12"}`（iframe 子树聚焦）；视口外提示 `[more content below the viewport]`；**"最后一帧快照=下一轮起始视野"纪律省一轮观察** |
| **严格模式选择器** | 实测：`span.titleline > a` 匹配 30 个 → 报错列出全部候选与可见/隐藏分类（`ElementResolutionError: matched 30 elements (30 visible, 0 hidden). Candidates: …`）；匹配 0 → 报错自带"page has been idle for 554ms with no DOM changes and no network requests in flight"（闲置检测量化进错误信息） |
| receipt 动作回执 | 实测：同 tab 导航点击 receipt=`{}`（仅报 popup/dialog）；先 arm `waitForEvent("popup")` 再点的协议 |
| 语义等待 + 自动滚入 | waitForURL/Selector/Function，禁固定 sleep；点击目标自动 wheel 滚入视野 |
| 隐身 | Page 会话向 CDP 隐藏 console（站点难检测自动化）；`egoAutomated.disable` 可还原 |
| 人机协作 | 指针动作 `label` → 页面可见 agent 光标；`openedBy:"unknown"` 视为用户页不许关；`waitForControl()/handOff()/adopt()/release()` 接管协议；实测 `finish({keep:[]})` 清理干净（listTaskSpaces 仅剩用户自己的空间） |
| 数据通道 | `evaluate`（实测取 title 成功）、`page.fetch`（页内 cookie/CORS 语义 + `saveAs` 二进制）、download/saveAs、`paste({text,html})` 富文本且恢复用户剪贴板 |
| 超时口径 | `page.click` 默认 **3000ms**——与 ZCode IAB 的常规预算 3000ms 完全收敛，可作为我们的默认预算依据 |

**量化观察成本**【实测】：example.com 全页快照 **1,179 字符**（~295 tokens）；news.ycombinator.com 视口快照 **34,707 字符 / 705 行 ≈ 8.7k tokens**。结论：a11y 快照通道单步 0.3–9k tokens，比截图+视觉（另有每次点击的坐标误差风险）经济且精确。

**许可注意**：ego lite 未确认开源与商用许可 → **只作机制与体验基准，不作为依赖**。

### 2.2 BrowserOS neo（AGPL-3.0 · 14,291★ · 2026-10-31 v0.52.0）【源码+API 核查】

仓库已重组为 `packages/browseros/`（Chromium fork + C++ patches）+ `packages/browseros-agent/{crates,apps}`（Rust server + TS 扩展）。核心机制全部经源码核实：

1. **稳定 ref 系统**（`crates/browseros-core/src/snapshot/refs.rs` + `observer.rs`）：
   - `[ref=eN]` 只发给可操作元素（`is_interactive_role(role) || cursor_hit` 且有 backendNodeId）；
   - 绑定 `StableNodeKey{document_id, frame_id, backend_node_id}`；编号单调**永不复用**；
   - 失效恢复：节点死后按 `role+name+nth` 在新 a11y 树中找回并写回缓存（observer.rs `resolve_ref_entry`）；`exact` blocker（无标签遮罩）绝不模糊恢复；
   - arrangement 哈希只取 `ref_id+role+frame_id`，**刻意排除文本**——注释原文：倒计时/广告轮播页每秒字节级变化，"is not a change of page"。
2. **act 三重保险**（`input/click.rs`）：scroll into view → 一次几何+hit-testing 读取 → **两次观测一致（<0.5px）才发** CDP Input 可信事件 → 移动后 final recheck；OOPIF 沿父 frame 链投影**至多 16 层**；DOM 兜底**至多一次**且如实上报；17 个动作枚举，`fill` 支持多字段批量（部分失败上报已填字段）。
3. **act 自动返回 diff**（full/summary/none/字符上限）；另有独立 `diff` 工具（查"自上次 snapshot/diff 以来的变化"，固定 full 粒度）。
4. **settle**（`settle.rs`）：注入 MutationObserver 计数到 `__browseros_ready`；**不等 networkidle/load/图片**；doc comment 原文："three of seven page opens returned on a 3000ms exhaustion rather than on any signal, and the work that followed each took under 25ms"。
5. **工具面（实测目录）**：22 个 catalog + 条件暴露（setViewport 仅 hosted；request_human_help/await_human_help 由用户开关）。要点语义：
   - `grep over="ax|content"`：直接在 a11y 快照行（保留 ref）或 body.innerText 上正则搜索——大页免全量快照；
   - `wait for="text|selector"`：超时**不抛错**返回 `{matched:false}`；描述建议 "act and read the diff instead of waiting"；
   - `read`：自研 markdown 转换器（content-markdown.js IIFE，无 Readability/Turndown），溢出写临时文件；`read_output` 分块读历史工具结果（16KiB，24h 过期）；
   - `credentials/payment_cards`：list/add/fill，**密码与卡号永不出现在结果里**；按浏览器版本 feature-gated（credentials ≥0.51.2.7 等）；
   - `evaluate_in_page`：唯一脚本工具（v0.0.87 release 原文："Read pages without running page script; evaluate_in_page is the only script tool"）。
6. **人机协作**：`request_human_help{reason, resumeHint, kind:"login"}` → takeover bar（`TakeoverContext{sessionId, agentLabel, reason, resumeHint?, site?, requestedAt}`）注入被阻塞 tab → 3 秒轮询 + visibilitychange 立即轮询 → 用户操作 → `takeover-resolve` 交还。
7. **登录态**：FAQ 原文 "Yes, that is the point. Agents drive BrowserOS neo using the sessions you already have"；per-agent profile 隔离在 roadmap。**不能 attach 外部 Chrome**——config 无自定义浏览器路径，"Everything assumes the connected browser is BrowserOS itself"。
8. **hosted/Docker 形态**：单镜像含 Linux 浏览器 + server，暴露 **9010 (MCP) + 6080 (VNC)**——有头浏览器 + VNC 远程访问，hosted 下才启用 CAPTCHA（CapSolver/2Captcha，默认 100 任务预算、单次 120s）与 setViewport。
9. **质量现状**（open issues 抽样）：#2592 "MCP action calls succeed without updating the page in CI"、#3094 "excessive snapshot output and CAPTCHA-blocked workflows"、#2307 Google 登录在用户 tab 中无法完成、#2156 瞬态 file input 上传失败——多步可靠性仍是它的痛点，印证「人机协作兜底」设计必要性。
10. **教训**：一年三次改名定位混乱；"为什么要整个浏览器"的路线之争；工具面从 53 → 22 收敛。

### 2.3 ZCode 官方 browser-use 插件 0.5.1（最接近"产品内置 agent 浏览器"的生产参照）【源码】

三层结构：node_repl MCP 宿主（进程内）→ `browser-client.mjs`（每个 fresh JS kernel 里 import，2,233 行）→ 宿主 BrowserControl（持久，持有 tabs）。**客户端对 iab/extension/cdp 三后端零特判**，后端差异只是 descriptor 的 `type` 字段，通信统一 `{browserId, generation, command}`——`generation` 让 stale wrapper 被宿主拒绝（版本化会话句柄）。

可直接平移到 eterna 的设计资产：

1. **文档系统**：`documents.json` 定义 included / lookup / when 三态——条件化文档按后端能力裁剪注入；截图类指南 lookup-only（不显式调用不进上下文）。`documentation()` 首次全量、后续复用模型上下文。
2. **API manifest 解释器**：`unsupportedByDefaultIn` / `requiresCapabilities` + Proxy 把不支持成员**在调用前隐藏**（get 返回 undefined、ownKeys 过滤），而非调用后报错。
3. **状态恢复协议**：fresh kernel + 持久 tab 的边界；"每个逻辑批次先独立返回完整 `tabs.list()` 供模型看见、下一 cell 才 `tabs.get(id)`"——"模型没看见的列表不算验证"。**popup 组合观察**：动作可能弹新 tab 时，单 cell `Promise.all([tabs.list(), user.openTabs()])` 双列表返回，防模型分两步决策跳过 popup 来源（源码中文注释记录了这条踩坑动机）。
4. **同站复用**：`open(url)` 复用同 hostname 的 agent-owned tab（全等→origin+path→hostname→父子域四级匹配）原地导航，防 tab 堆积。
5. **错误模型**：`BrowserCommandError{code, command, result}`；快照重建纪律（失败禁止重试同一 locator）。
6. **安全**：页面内容 UNTRUSTED 是纯 prompt 纪律；**机器强制的只有**：capability 成员隐藏、viewport 硬限（320-3840×320-2160 拒绝而非 clamp）、文档 lookup 门。
7. **Electron 宿主特有、web 部署需替换**：bridge Symbol 注入（同进程）、IAB pane 可视性、recording（Electron WebView+MediaRecorder）——web 部署以"服务端 session/tab 表 + WebSocket 命令通道"替代 bridge，协议层可平移。

### 2.4 DSH 内核浏览器栈（逐行审计结论）【源码】

**框架**（`packages/browser-use/browser-use`）：`BrowserUseRegistry` 独占槽位服务——只登记 provider 名、拒第二个（`index.ts:35-38`），无任何浏览器操作方法（docs:17 原文印证）。

**资源生命周期**（`packages/experimental/browser-use-runtime`）：
- 资源 keyed by **live Agent**（`entries: Map<Agent, Entry>`，index.ts:61）；惰性 spawn（MCP 路径在 `agent/created` 串行事件里完成连接+发现，stagehand 首次工具调用才 launch）；
- Agent 释放 → effect 触发 `closeEntry`：abort → close → 等 tail（:185-196）。MCP=杀子进程；stagehand launch=Worker terminate + `browser.kill()` + 删临时 profile；
- **"跨 turn 保留"仅限同一激活**；"resumed Session 不继承"（README:50：防"同 durable id 的恢复 Session 继承上一个浏览器"）；
- 操作经 `entry.tail` promise 链**串行化**；跨 Session 各自独立；
- **attach 互斥**：`exclusive:true`——浏览器忙时新激活整段置 `blocked`（浏览器工具从该 Agent mask 掉、prompt 里也没有 mcp section，且**永不重试**，release 后只有新激活可取）。

**三 provider 精查**：

| provider | 钉版 | spawn 参数要点 | 关键限制 |
|---|---|---|---|
| playwright-mcp | `@playwright/mcp@0.0.80`（上游最新 0.0.84） | `--browser chromium`；launch：`--isolated`（+headless/executable-path，清洗 `PLAYWRIGHT_MCP_*` env）；attach：`--cdp-endpoint` | **launch=内存 profile 无登录持久**；attach 才保登录；toolOrder 须留 `<unlisted-tools>`（显式列出会让无浏览器连接的 Session prompt assembly 失败，README:50） |
| chrome-devtools-mcp | `1.9.0`（上游最新 1.12.0） | `--no-usage-statistics`；attach：`--ws-endpoint`/`--browser-url`；launch：`--isolated --headless=<bool>` | 同 launch isolated 问题 |

## 5. 路径决策分析（证据评估）

### 5.1 浏览器运行时形态（D2）

| 选项 | 证据评估 | 结论 |
|---|---|---|
| **A. 服务端每用户常驻 Chromium + attach** | DSH attach 模式是唯一保登录态的官方通道（launch 硬编码 `--isolated`）；attach 互斥语义（一激活一浏览器）天然匹配"每用户一个浏览器"；NAS 已跑 chrome-novnc 证明拓扑；BrowserOS hosted 同构（浏览器+VNC+MCP 三件套）；noVNC 直接嵌面板可绕开 iframe 跨域痼疾 | **推荐**。Chromium 作为独立 sidecar 服务（每用户或每租户），eterna 主容器经 CDP attach |
| B. launch 模式（DSH 默认起一次性浏览器） | 零运维、代码零改动，但 `--isolated` 内存 profile → **每次激活全新浏览器、无登录态**，ego lite/BrowserOS 的核心价值（复用登录）全部落空 | 仅作 M1 冒烟/无登录场景 |
| C. 维持 iframe 面板 + agent 独立 headless | 最小改动，但 iframe 痼疾（XFO/跨域不可读/B-F 失效）永存、两轨永不合流 | 仅作过渡 |

### 5.2 Agent 工具面路径（D3，v2 收窄）

- ~~stagehand-native~~：**排除**（DeepSeek 不支持 + 缓存仅云端 + 需额外模型 key）。
- chrome-devtools-mcp：**降级为可选补充**（61 工具更重；调试能力 performance/network 留给 M5 后按需）。
- playwright-mcp（0.0.80 钉版）：**M1 快路径成立**（五包已发布、两步挂载、机制业界标准），但 0.0.84 已 72 工具 → 上游趋势是膨胀，长期必换。
- **自研精简工具面**：必要性升级——目标形态为「插件层自建 browser-use provider 或 MCP Server」（自建清单本就含 MCP Server 层）：~12 个 ego-lite 风格工具（tabs/navigate/snapshot/click(element,ref)/fill/press/wait/evaluate/screenshot/extract/download/read），感知直接用 **playwright-core 1.65 本体 API**（`ariaSnapshot({mode:'ai'})` + `getByRef()`——ref 机制已上升为 Playwright 公开 API，不必自己啃 CDP a11y 域）；参照 ZCode 的 manifest 裁剪/文档三态/组合观察协议与 BrowserOS 的稳定 ref/settle/diff。

## 7. 安全与合规边界（v2 微调）

1. **出站面**：Chromium sidecar 是第二个公网出站面；容器网络层面限制——sidecar 仅 eterna 主容器可达其 CDP/VNC 端口（compose 内部网络，不映射宿主端口）；egress 白名单管控出站（D1）。
2. **注入防御**（采纳各方收敛结论）：页面内容一律 untrusted 仅用于定位；禁止执行页面内嵌指令写进 prompt 硬规则；M5 可选分类器；工具实现层把快照文本包装为数据（参照 ZCode：纪律靠 prompt，机器强制做在能力裁剪与参数校验层）。
3. **敏感动作**：密码/支付类默认禁止清单；密码框自动掩码+截图跳过（BrowserOS 语义）；credentials 类工具如做，密码永不出现在工具结果里。
4. **登录态**：sidecar profile 属用户敏感数据（state 文件=密码）：每用户隔离卷、加密落盘、随用户删除；attach 互斥语义天然防跨用户并发。
5. **与 eterna-access 关系**：门禁管进门、egress 管出门；面板/sidecar 流量走既有鉴权与同源反代。
