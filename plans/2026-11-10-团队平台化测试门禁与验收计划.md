## 1. 总则（A）

### 1.1 门禁判定原则

1. **每条门禁 = 「量化判据 + 执行命令 + 证据落盘路径 + 失败处置」四元组**。判据只允许三种形态：
   - **数字**（测试通过数、findings 数=0、文件字节数 ≤ 阈值、截图张数、耗时上限）；
   - **枚举**（exit code ∈ {0}、verdict ∈ {pass/fail/exempt}、视图字段 ∈ {本人 id 集合}）；
   - **文件存在性**（证据路径存在且非空，JSON 可解析）。
2. **机器判定**：每阶段一个 gate 脚本（§2）聚合全部 case，产出 `gate-summary.json`；`verdict` 字段就是 go/no-go——`fail` 数 > 0 ⇒ `no-go`，阶段不得放行。
3. **断言看响应体，不只看状态码**（同源闸教训 + typert 帧_protocol 现实）：一切 HTTP 越权用例必须断言响应体（拒绝帧中文文案或结构化 error 字段）；一切「不泄漏」用例必须做响应体**负向包含断言**（如 key 值全文检索 = 0 命中）。
4. **证据可追溯**：每条证据文件路径在本计划写死（§1.2）；gate-summary.json 内 `evidence` 数组指向相对路径；`acceptance/INDEX.md` 增行登记（沿 companion 门禁治理惯例）。
5. **无人值守防作弊**：gate 脚本对「期望值」与「实测值」都落盘；实测值由脚本自采（exit code / 解析输出 / fs 检查），不接受实现者口述。

### 1.2 证据落盘约定（路径写死）

```
acceptance/team-platform/
  p0/ … p4/                     ← 每阶段一目录
    gate-summary.json           ← 机器可判定摘要（schema 见 §2.3）
    evidence/<GATE-ID>/         ← 该门禁的原始工件（日志/JSON/截图/对账表）
  release/
    gate-summary.json           ← 最终放行清单汇总
    evidence/<G-REL-ID>/
gui-test-screenshots/team-platform/<p1|p2|p3|p4>/   ← 视觉证据统一批次
```

- 阶段内 E2E 运行态（DSH home、测试容器）一律隔离：`.eterna-home-tp-<场景>`（沿 `.eterna-home-t7`/`.eterna-home-gov-e2e` 先例），跑完 `rmSync` 或保留至阶段放行后清理。
- 测试账号种子（tp-admin / tp-alice / tp-bob）与随机密码写入运行态 `gate-env.json`（0600，系统临时目录；沿 browser-relay gate-setup 先例），**不进 git**。

### 1.3 失败处置与豁免规则

| 情形 | 处置 |
| --- | --- |
| 任一门禁 `fail` | **阶段不得放行（no-go）**。修复后重跑**该阶段全量 gate**（非单条），以最后一次 gate-summary.json 为准 |
| 外部依赖不可用（如 MiMo web_search 控制台未开通、公网入口当日不可达） | 唯一允许跳过的形态 = **文档化豁免**：`gate-summary.json` 该 case `verdict:"exempt"` + `exemption{reason, remedy, approvedBy:"用户"}`；豁免必须写明原因与补救路径（如「控制台开通后补跑 G-P2-06，并入 release-gate 必跑项」）。**豁免不计 fail，但 release-gate 会复核豁免清单与补救状态** |
| 测试本身发现产品缺陷 | 门禁红即缺陷登记：evidence 目录留 `defect.md`（现象/最小复现/影响面），修复后门禁转绿方可放行 |
| 环境级失败（容器起不来、端口占用） | 如实失败（沿 perf-realsession「不伪造」纪律），evidence 留完整 stderr；禁止删证据重跑刷绿——gate 脚本对每次运行追加 `runs[]` 记录 |

### 1.4 阶段间回归：核心回归子集（CORE-REG）

每阶段放行前（P1 起）与最终放行前必须全绿，固化为每阶段 gate 的**第一条门禁**（`G-Px-01 = CORE-REG`）。实现为 `scripts/team-platform-gates/core-reg.mjs`（一次性编排，逐项输出 PASS/FAIL，退出码聚合）：

| # | 子集项 | 命令/断言 |
| --- | --- | --- |
| C1 | access 守卫矩阵全量 | `pnpm --filter @eterna/access run test` exit 0 |
| C2 | governance / glue 回归（pre-execute 挂法所在包） | `pnpm --filter @eterna/glue run test` exit 0 |
| C3 | 隔离铁律扫描 | `node tools/packctl/bin/packctl.mjs tenant-scan` 输出 `0 finding(s)` |
| C4 | 真装载冒烟（web 档） | `node scripts/verify-eterna-web.mjs` exit 0（物化→boot→pluginInventory：0 failed、0 skipping/incompatible、保留行 enabled+active） |
| C5 | 安全 E2E 核心三条（P1 建成后自动纳入） | ① 他人 sessionId HTTP 直调被拒（响应体断言）；② 他人 sessionId mux follow 拒/空流；③ symlink 越根拒——由 `p1-e2e-guard.mjs --subset core` 执行 |

> CORE-REG 的执行位置 = 各阶段 gate 脚本 case[0]，命令 `node scripts/team-platform-gates/core-reg.mjs`；产物落 `acceptance/team-platform/<phase>/evidence/G-Px-01/`。

### 1.5 执行环境与红线约束（C 部分固化）

1. **绝不触碰生产**：所有 E2E/真连/沙箱测试在「本地 boot 实例」或「一次性测试容器」执行；**rebuild + 重部署由用户执行**（纪律 `no-touching-running-deployments`），测试只对用户新部署的**验收实例**做只读+测试账号操作。
2. **浏览器 E2E 双档纪律**（同源闸教训）：
   - **本地验收档**（高频迭代用）：`ETERNA_ACCESS_SECURE` 不设、`http://127.0.0.1:<port>`（browser-relay gate-setup/gate-run 实测可行的形态）；
   - **公网验收档**（阶段门禁最终证据必含）：`https://eternity-electricity.cn:3210`（SECURE=1 生产形态：Secure cookie/反代 WebSocket/同源闸全链真实），目标为**用户为该阶段重部署的验收实例**。每阶段至少一轮公网档 E2E 证据；本地 http 源在 SECURE=1 实例上 403 属预期行为，测试脚本不得绕闸。
3. **凭据纪律**：三家 key 只存 `.secrets/{deepseek,mimo,glm}-api-key.txt`（0600，gitignored）；**凡带凭据的探测/真连一律由 node 脚本从 `.secrets` 读入内存**（perf-realsession 先例），禁止 `$(cat …)` 内联进 shell argv；key 不出现在任何证据文件/日志/截图（截图含配置分区时须确认 UI 只显 apiKeyEnv 名与已配置状态——这本身是 G-P2-10 的断言面）。
4. **沙箱/终端实调在一次性 Linux 测试容器执行**（`docker build -f Dockerfile -t eterna-tp-test .`，跑完即删，绝不挂生产 volume、不触运行中容器）——理由：生产基镜像 node:24-bookworm-slim @ Linux landlock（T0.1 probe=full 实测），macOS 本机是 Seatbelt 档，为忠实生产形态必须 Linux 容器。
5. **上游与参考仓只读**：deepseek-harness、`/Users/sunny/code/zcode-ref` 均只读（G-P0-10 断言 zcode-ref 工作树干净）。

## 2. 门禁执行器设计（gate 脚本契约）

### 2.1 目录与脚本

```
scripts/team-platform-gates/
  common.mjs                 # 判定内核：runCase/聚合/落盘（无业务）
  env-up.mjs                 # 本地验收档环境编排（物化 profile→boot→种子账号→gate-env.json）
  core-reg.mjs               # §1.4 核心回归子集
  p0-gate.mjs … p4-gate.mjs  # 每阶段门禁跑批
  ph-gate.mjs                # PH 生产热修复门禁跑批（v3，--case rules-live/fullaccess-turn/eye-shift/verify-probe/allowlist，--public 公网复验）
  release-gate.mjs           # 最终放行清单
  # 阶段 E2E 采集脚本（供 gate 调用，也可单跑）：
  p1-e2e-guard.mjs           # 守卫矩阵 HTTP+mux 双路（--subset core 可只跑 C5 三条）
  p1-e2e-sandbox.mjs         # 沙箱逃逸矩阵（Linux 测试容器内）
  p1-e2e-terminal.mjs        # 终端替换件 E2E
  p1-e2e-directory-tree.mjs  # 目录树 UI E2E
  p2-live-matrix.mjs         # 三家真连矩阵（key 自 .secrets 读入内存）
  p2-key-leak-scan.mjs       # key 不回传负向断言（扫全部配置读接口响应体）
  p3-bundle-report.mjs       # ECharts 体积报告（build 前后对比落盘）
  p4-e2e-promote.mjs         # 转内置全链路
  p4-e2e-user-delete.mjs     # 删用户级联销毁 + 幽灵用量对账
```

### 2.2 执行器输入输出契约

- **输入**：环境变量 `GATE_PHASE`（p0…p4/release）、`GATE_HOME`（隔离 DSH_HOME，默认 `<repo>/.eterna-home-tp-<phase>`）、可选 `--only <GATE-ID>`（单跑）、`--exempt <GATE-ID>=<原因>`（登记豁免，最终以用户确认为准）。
- **执行**：逐 case 按该 case 声明的 command/fn 执行，**实测值自采**（exit code / 输出解析 / fs 检查 / HTTP 响应体解析）。
- **输出**：stdout 逐条 `[PASS]/[FAIL]/[EXEMPT] <GATE-ID> <实测值>`；`acceptance/team-platform/<phase>/gate-summary.json`；**退出码 = fail>0 ? 1 : 0**。
- 模式渊源：browser-relay `gate-run.mjs` 的「跑批+证据落盘」形态，加上本计划新增的**聚合判定层**（gate-run 只采集不判定，判定交人；无人值守场景必须由脚本判）。

### 2.3 gate-summary.json schema（机器可判定）

```jsonc
{
  "phase": "P1",
  "gateScript": "scripts/team-platform-gates/p1-gate.mjs",
  "git": { "commit": "<sha>", "branch": "feat/team-platform", "dirty": false },
  "startedAt": "2026-11-XX T…Z", "finishedAt": "…",
  "cases": [{
    "id": "G-P1-04",
    "criterion": "session/events 直调他人 sessionId 返回拒绝帧（响应体含『会话不存在或不属于你』）",
    "command": "node scripts/team-platform-gates/p1-e2e-guard.mjs --case events-cross",
    "expect": "deny-frame",              // 数字 | 枚举 | 文件存在性
    "actual": "deny-frame",
    "verdict": "pass",                   // pass | fail | exempt
    "exemption": null,                   // 或 { reason, remedy, approvedBy }
    "evidence": ["acceptance/team-platform/p1/evidence/G-P1-04/record.json"],
    "durationMs": 1834
  }],
  "summary": { "total": 20, "pass": 19, "fail": 0, "exempt": 1 },
  "verdict": "go"                        // fail==0 ⇒ go；否则 no-go
}
```

放行定义（量化）：`verdict == "go"` 且豁免全部有 `remedy` 且已登记 `acceptance/INDEX.md`。
