> 生成：2026-11-24 ｜ 状态：**待执行**（访谈四轮已收敛，无未决产品决策）
> 关联：`53-主会话上下文治理-orchestrator特化压缩与话题分治.md`（§2-3 缺口）、`52-会话级super标记与任务设置分区.md`、`frontend-style.md`

## 1. 一句话目标

在会话右侧栏提供一个**独立于主会话上下文的辅助对话**（专属 tab，可多开），它按需只读主会话的实时与历史内容、工作区文件、知识库与工单状态，产出的结论由用户**一键确认**后以 `inject`（不唤醒）或 `followup`（自成一轮）两种语义之一投递给主会话；主会话上下文零污染、token 只按需付。

**成功标准**：用户在会话中对「这个方案你怎么看」这类追问，能在参谋 tab 里多轮讨论而不让主会话上下文增长；讨论结论一键送进主会话并生效；主会话侧无任何「多了一个子代理」的模型层行为变化（除经过提示词纪律约束的 catalog 可见性，见 §7 R1）。

## 2. 背景

### 2.1 触发因素（访谈原话转述）

用户希望有一个类似 ZCode「side conversation」（`sidePane.selectionChat`，atern 实证：独立 `childSessionId` + `parentSessionId` + `ordinal` 多开）或 Claude Code `/btw` 的机制：**辅助对话能拿到主会话实时与历史内容，并且能给主会话发消息补充信息**。

### 2.2 现状（全部实测，2026-11-24）

| 事实 | 证据 |
|---|---|
| agent-basis **无**任何侧边对话/side chat/辅助对话实现或计划 | 全仓 `rg -i "side.?chat\|辅助对话\|旁侧对话\|btw"` 排除 node_modules 后零命中 |
| dsh 内核**无** side chat 实现；但有全套能力底座 | `deepseek-harness` 全仓检索（详见 §10 来源） |
| 右侧栏承载面完备：`ctx.sidebarRight` 导航控制器 + `sidebarRightTabs` tab 类型注册表 + `ui-dockkit` 分栏/浮动 | `packages/client/ui-sidebar-right/README.md`:§Extension seats、§`ctx.sidebarRight` |
| 子会话嵌进右栏的**完整上游先例** | `packages/client/ui-subagent/src/client/sidebar-chat/` 注册 `dsh-resource://subagentchat/session/<child>?parent=&mode=` + builtin tab type + `sidebar.chat.conversation` slot |
| 读主会话（实时/历史）齐备 | `ctx.sessionQuery.readSurface(id)`（`session-query/src/index.ts:310`）、`readSession(id)`（`:184`）、`listEvents`（`:269`）、`filterEvents`（`:282`）；实时事件 `session/event`（`core/session/src/index.ts:76`） |
| 写主会话三档语义 | `Agent.inject()`（下一 step、不唤醒）/`followup()`（自成一轮、唤醒）/`steer()`（最近 step）——`core/agent/src/runtime-types.ts:236-277` |
| 带父历史的子会话 | `subagent-fork-in-process`（`providerName: fork`），种子 = 父会话**已完成 turn 前缀**，**一次性快照**；`startActivation({provider, childId, delivery:'caller'})` 可程序化创建（`subagent/src/index.ts:252-290`） |
| 两个 subagent 后端在 base bundle 且 eterna 未裁切 | `packages/bundle/base/cordis.patch.yml:374-382`；`profiles/eterna-web|cordis.patch.yml` 无相关裁切行 |
| 普通侧栏**原生省略** subagent 会话 | `ui-subagent/README.md`:「The ordinary sidebar omits subagent conversations」 |
| subagent child 仍进父 catalog | `SubagentActivationSpec.delivery` 注释：「Local children always enter the parent catalog」——**模型层可见**（见 §7 R1） |

### 2.3 与 53 号既有拍板的关系（**必须正面回应**）

`docs/design/53-*.md:91` 定稿「明确不做：把主会话拆成多会话……话题隔离由工单承担」。**本计划不违反该拍板**，理由：

1. 该拍板禁止的是**拆主会话**（把一条主会话流劈成多条），本计划主会话一条流不变；
2. 同文档 `:62` 明确指出待补的洞正是「用户在主会话里的**纯对话**（没开工单的多轮讨论）没有等价的结构化保护」——参谋面板正是这个洞的旁路容器；
3. 参谋会话**不承担**话题执行，只承担「想清楚」，结论回灌主会话；执行仍走工单（D1 话题分治纪律不动）。

**结论**：本功能与 53 号互补，不是翻案。计划书评审时须首先确认这一条。

> **✅ 2026-11-24 用户已认可**（两形态都装）。同时裁定两条落地要求：
> ① 53 号 §4「明确不做」旁已加交叉引用（定稿文本未改）；
> ② **D1 提示词行须由二分扩为三分**（需执行→工单 / 需多轮但不执行→参谋 / 一句话→就地答），保留「长期有效事实→记忆」以防事实滞留侧会话——该修订随本计划 P8 落地，并回填 53 号 P4 的记录口径。
>
> 需要注意的真实张力：不改 D1 会出现两种偏差——把该讨论的过度转工单（白占执行槽位），或用户用参谋绕开 D1 直到结论才回灌（执行必须进工单这一步被延后）。这是 P8 的验收内容，不是文档修饰。

## 3. 访谈结论（已确认决策）

| 维度 | 结论 |
| --- | --- |
| **架构** | 独立 session + **工具化按需读父**（不做实时全量镜像；父上下文不翻倍） |
| **定位** | **顾问/参谋**：只读，不写文件、不执行命令、不委派 |
| **回写** | **用户确认后投递**，面板提供**两个按钮**：`inject`（不唤醒，下次发言才见）与 `followup`（自成一轮，立即处理） |
| **会话归属** | **subagent child**（`provider: fork`，`delivery: 'caller'`）——复用内核 catalog/持久化/冷恢复；左侧会话列表不可见（P0 实测：靠客户端 `tree.ts:235` 硬过滤，宿主语料仍含，见 §7 R1b） |
| **挂载形态** | **base 与 super 两形态都装**（2026-11-24 用户裁定；super 主会话正是 53 号诊断的膨胀重灾区，收益最大） |
| **入口** | ① 右侧栏 tab（主入口）② 斜杠命令 / 快捷键 ③ 选中文字入口（`conversation.chat.text-interaction`） |
| **工具面** | 读主会话历史 + 读文件（只读）+ 知识库检索 + 读工单/任务状态（后者仅 super 形态） |
| **生命周期** | **持久 + 可多开**（tab type 声明 `multiple: true`） |
| **界面区分** | 专属图标 + 称号「参谋」（走 `@eterna/ui/icons`） |
| **主会话感知** | 目标「完全不可见」；**机制上残留 catalog 可见**，靠提示词纪律兜底（§7 R1）。P0 实测：宿主 `listSessions` **仍含**参谋会话，列表隐藏靠客户端 `tree.ts:235` 硬过滤——**其他消费面（导出/API）仍可见**（§7 R1b） |
| **承载落点** | `sidebar.right.pane.tab`（keyed）+ 复用 `conversation.content` Factory（`variant: 'embedded'`） |

## 5. 范围

**做**：

- 新包 `@eterna/adviser`（Host 半边 + 客户端半边），走 dsh 原生扩展点；
- 右侧栏「参谋」tab 类型（`sidebar.right.pane.tab`，`multiple: true`），复用 `conversation.content` embedded Factory 渲染完整对话；
- 参谋会话的创建/落座（`ctx.subagents.startActivation({provider:'fork', label, childId, request:{parent, prompt}, signal, delivery:'caller'})` —— **P0 实测签名，`parent`/`prompt` 嵌在 `request` 内**）、冷恢复、多开管理；
- 参谋侧只读工具集：`adviser_read_parent`（读主会话当前面/历史段/某回合）、`adviser_search_parent`、只读文件读、知识库检索、工单状态读；
- 参谋 agent preset `eterna-adviser`（只读工具面 + 压缩组）；
- 回写双按钮 UI + 投递实现（`inject` / `followup`），含二次确认与投递结果回执；
- 三个入口：右侧栏 tab、斜杠命令 `/adviser`（或快捷键）、`conversation.chat.text-interaction` 选中文字入口；
- 专属图标（`@eterna/ui/icons`）+ 称号文案（中文）；
- 主会话侧提示词纪律：声明参谋子会话为「用户私人旁注，不得寻址/不得等待其输入」；
- 四处 profile 挂载 + 门禁脚本行表更新 + `packctl` 相关登记。

**不做**：

- ❌ 不实时镜像父会话（访谈已否，成本翻倍）；
- ❌ 不给参谋写权限（不写文件、不跑命令、不委派、不建工单）；
- ❌ 不改主会话上下文结构、不动压缩参数（53 号 P0–P4 归其自身计划）；
- ❌ 不做「把主会话某段迁移进参谋」的历史搬移（若将来需要，`surfaceOp: replace` 原语已具备，另立计划）；
- ❌ 不让主会话主动调用参谋（访谈已否）；
- ❌ 不做跨设备同步（布局本就是 browser-local）。

## 7. 风险与对策

| # | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| **R1** | **模型层残留可见**：subagent child 恒进父 catalog，`list_agents` 能列出参谋；`send_message` 能给它发消息 | 主会话可能「多余地」发现并寻址参谋，破坏「不可见」预期 | ① 提示词纪律明确声明参谋为「用户私人旁注，不得寻址、不得等待其输入、不得改写」；② P8 加回归用例；③ 若残留仍刺眼，升级方案 = 改 `delivery:'caller'` 的 catalog 语义（需上游改动，本计划不碰） |
| **R1b** | **宿主语料仍含参谋会话**（P0 实测）：`ctx.sessionQuery.listSessions()` 返回父与子两条；「列表不可见」只是客户端 `tree.ts:235` 的硬过滤 | 导出、API 调用方、其他 UI 消费面仍能看到参谋会话——「会话列表不可见」不等于「会话不存在」 | ① 对外口径明确：这是**界面隐藏**，不是数据隔离；② 若需真隔离，须改宿主列表投影（上游改动，本计划不碰）；③ P10 文档写清边界 |
| **R2** | fork 种子是**一次性快照**，参谋看不到 fork 之后父会话的新内容 | 参谋可能基于过期上下文给建议 | 这是设计的核心取舍：靠 P4 的 `adviser_read_parent` 工具在需要时拉最新；面板上显式标注「已同步至 seq N」并给「刷新」按钮 |
| **R3** | 参谋只读但可读**父会话之外**的会话（越权） | 多租户隔离破坏 | 工具实现严格走 access 守卫层口径；P4 必须有 cross-tenant 负用例门禁 |
