# 可执行计划书：会话动态思考强度——判档质量迭代（V2）

> 生成：2026-11-18 ｜ 状态：执行中（内核/反馈/工具已交付，语料与 E2E 待办）

## 1. 一句话目标

在既有「每轮一决策」自动思考强度链路上，把判档依据从**单条消息**扩展到**会话上下文**，并建立用户显式纠正闭环；以离线回放门禁证明"变准了"：

- 回放集（生产日志抽样 + 人工标注）上：**相邻档命中率 ≥ 90%**、**与人工目标档一致率 ≥ 60%**、**极端误配 0 例**（寒暄取最高档 / 代码排查取最低档）；
- 三个指标**不劣于 V1 同集成绩**；
- 上线后在线监控：`access.thinking.feedback` 计数、「想多了/想少了」点率、审计中 score/effort 分布可解释。

数字口径：门禁线为**用户本轮拍板**；实际成绩必须由 `scripts/thinking-replay.mjs` 实测输出并写入 PR 描述，禁止估算。

## 2. 背景

产品已有 V1（提交 `a412357`，文档 `docs/dev/thinking-auto.md`）：真人消息入箱时按纯启发式评分选档，整轮固定、默认开启、手动拖滑杆即退出、fail-neutral、审计可回放。V1 的三处结构性弱点：

1. **只看单条消息**：不知道上一轮工具刚失败、不知道用户在追问同一问题、不知道会话已很长；
2. **不回应用户纠正**：用户只能整体退出自动，纠正信息零回流；
3. **档位映射粗糙**：`round(score*(n-1))` 在 3–6 档模型上做线性映射，缺少难度分档校准。

本轮按「判档质量优先」迭代这三处，不碰轮内升降档与小模型路由（二期）。

## 7. 设计要点（实现约束）

### 7.1 会话上下文信号（初始值，回放校准后定稿）

| 信号 | 来源（会话事件） | 方向/幅度 |
| --- | --- | --- |
| 上轮工具失败 | `tool/result` 且 `message.isError` | 每个 +0.15，封顶 +0.3 |
| 同类工具连续失败 ≥2 | 同上，按 `name` 聚合 | 额外 +0.15 |
| 同题连续追问 | 与上一条 `user/message` 文本 n-gram 重叠 ≥0.6 且间隔 ≤10min | +0.15 |
| 上下文规模 | 窗口内事件数 ≥200；近 3 轮文本总字符 ≥20k | +0.1 / 再 +0.1 |
| 上轮档位弱先验 | `agent.model.current().reasoningEffort` 归一档位 | ±0.05（无增益则删） |
| 反馈偏置 | `sessions.thinking_bias`（读时 24h 半衰） | 直接叠加，最终钳 0–1 |

规则：显式指令（想深入/简短回答）仍**一锤定音**，上下文信号只在非显式路径叠加；`scoreMessage` 保持纯函数，上下文由路由器组装后传入。

### 7.2 偏置语义

- 每次点击：`bias += ±0.2`，钳位 `[-0.5, +0.5]`，`thinking_bias_at = now`；
- 读取时按 24h 半衰计算有效偏置；偏置过期（有效值 <0.01）视为 0；
- 手动拖滑杆仍=退出自动（V1 语义不变），**不**产生偏置；
- 重置入口：模型菜单「自动」chip 的长按/二级项（沿用现有菜单，不新增页面）。

### 7.3 反馈 RPC 契约

```
POST /api/session/thinkingFeedback
request: { sessionId, messageId, direction: 'less' | 'more' }
response: { bias: number, effectiveBias: number }
```

守卫与先例同构（`tenant.ts` 通用循环 + sessionOwner 比对）；审计 `access.thinking.feedback` 带 `{sessionId, messageId, direction, bias, effectiveBias}`。

### 7.4 铁律对照

- 前端：只注册 dsh 原生 slot（settings/assistant-actions），零新页面；`--et-*` 令牌；图标走 `@eterna/ui/icons`；文案中文；深浅两主题截图；
- 多租户：新 RPC 必须有归属守卫 + tenant 单测；偏置写入永不带 `account` 参数以外的租户推断；
- 数据不出内网：语料/日志只在本地未跟踪目录，不写审计正文、不进镜像、不入库；
- 可访问性：按钮 aria-label、focus 光圈、`prefers-reduced-motion`。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `snapshotEvents` 尾部窗口在长会话上变慢 | 入箱延迟、破坏"全同步"纪律 | 窗口上限（近 200 事件/3 轮）；实测 p95 记入 PR；超阈值退回 `ownEvents` 尾部切片 |
| 生产语料分布偏差（多为短问） | 门禁数字虚高、上线后失真 | T2 分层配额 + 报告每层样本量；极端误配单独计数 |
| 启发式天花板：一致率达不到 60% | 门禁不过、迭代卡住 | 先出数定位（混淆矩阵哪个档错），必要时把模糊带交二期小模型；**不为过线改标签** |
| 反馈误点/连续点击 | 偏置失控 | 钳位 ±0.5 + 衰减 + 可重置 + 审计留痕 |
| 新增 slot 注入导致 client 静默不激活 | UI 不渲染（历史事故） | 先做最小冒烟（控制台无报错、slot 计数）；不改 client inject 清单以外的依赖 |
| 同步监听体抛错阻断步进 | 会话不可用 | 沿用 try/catch + `ok:false` 审计（fail-neutral） |
| 语料含个人信息 | 合规 | 复用 PiiFilter 规则脱敏；语料目录 gitignored；PR 只放聚合数字 |

## 9. 验证方式

1. 单测：`pnpm --filter @eterna/access run verify`（新增信号/窗口/迁移/RPC 守卫）；
2. 回放门禁：`node scripts/thinking-replay.mjs --corpus <本地语料> --gate`，输出三个指标与混淆矩阵；
3. 全量：push 前 `pnpm -w run verify`（20 包全绿，历史教训）；
4. E2E：独立容器（零接触生产）跑五场景，附审计记录与深浅截图；
5. 上线后监控：审计 `access.thinking.feedback` 计数、feedback 点率、`access.thinking.auto` 的 score/effort 分布；异常（点率 >20% 或高档占比 >60%）回滚到 V1 常量表。
