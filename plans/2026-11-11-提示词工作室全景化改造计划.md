# 可执行计划书：提示词工作室全景化改造（前端挂载 · 全景开放 · 注入规范重构）

> 生成：2026-11-11 ｜ 状态：待执行 ｜ 建议落点：新 worktree/分支 `feat/prompt-studio-v2`（基于 `origin/main`；当前 `fix/access-tenant-bootstrap` 有未提交改动，勿混行）

## 1. 一句话目标

把提示词工作室（`packages/prompt-studio`，T7）从「只管 preset-standard persona 前缀一行、生产未挂载」升级为**全产品提示词唯一管理面**：生产 profile 可见（前端挂载）、三层提示词全景可查可改（admin + R3 审批）、写穿 configEditor 热生效（不重启）、版本化回滚、会话粒度快照（新会话读最新、历史会话沿用历史）、packctl 门禁强制「提示词类插件必须登记」、AI 润色/审核（建议稿 + diff 预览 + R3 生效）。

成功标准：
1. eterna-web 生产 profile 打开产品即见提示词工作室面板，三层提示词全部可查看；
2. admin 修改任一条目经 R3 两段式审批后**不重启**对**新开启会话**生效（E2E 实测：改 persona → 新会话立即用新文，旧会话沿用快照旧文）；
3. 任一条目可回滚到历史版本（回滚=前滚写新版本，语义不变）；
4. `packctl` 新门禁：涉及提示词工程而未登记的插件/包被 CI 拦截；
5. AI 润色产出建议稿 diff、AI 审核产出问题清单，二者均不直接生效；
6. 每期过 acceptance gate（深浅两主题截图 + 断言证据入 `acceptance/INDEX.md`）。

## 2. 背景

- **触发因素（用户 2026-11-11 提出）**：①产品里看不到提示词工作室页面；②要求全产品提示词前端可查可改 + AI 润色/审核；③重构 agent 基座提示词注入规范——覆盖所有 agent 提示词与插件，设插件接入门禁，会话开启读最新、历史会话沿用历史。
- **现状（已核实）**：
  - 工作室**有前端**（`StudioPage.tsx` 606 行 + `TracePage.tsx`，两个 `main` keyed 面板 + sidebar 入口，`packages/prompt-studio/src/client/index.ts:27-32,124-159`），但 `profiles/eterna-web/cordis.patch.yml` 与 eterna-embed **均无 insert 行**——只有测试 harness 挂载，故产品不可见。
  - 管理面仅一条：`preset-standard` 行 `plugins[id=persona].config.prefix`（`src/persona-patch.ts` patch 行纯文本重述写回 + 写后 `dsh --dump-config` 干跑自检）。
  - 提示词全景三层均在工作室外：
    - **preset 层**：`profiles/eterna-web/cordis.patch.yml` 两预设的 `persona.prefix`、`agent-instructions`(maxBytes)、`time-context`、`plan-mode` 的 `config.section` 整段、compaction 等（上游 `@deepseek-ai/dsh-*` 插件 config）；
    - **领域层**：`packs/event-planning`、`packs/industrial-analysis` 的 `system-prompt.personaPrefix` + 各自 `persona.md` 全文 + 领域 skills；
    - **运行时层**：`ctx.systemPrompt.section` 动态注入（现存使用者：memory、glue）。
  - **上游契约（`@deepseek-ai/dsh-system-prompt` 官方 README + types）**：提示词**每个模型步骤动态组装**（`assemble(context)`，`lib/types/index.d.ts:37-45`）；`PromptSection.text` 支持按次求值的 provider（`:60`）；存在 **`system-prompt/assemble` cooperative waterfall 监听**（`:27`，可对每次组装的段落改写）——历史会话回放的理论通道；`AssembleContext` 仅 `scope`/`signal`，**无显式会话 id**（首要技术风险）。
  - **热生效先例**：llm-doctor 经官方 `configEditor` seam 写回 patch **热生效**（`packages/llm-doctor/src/index.ts:5,105-120`）——无需重启的官方通道。
  - **写治理已备**：R3 两段式审批（ruleId `eterna.prompt-studio.persona-write`）、DSH_HOME 版本库（一版一文档只增不删）、审计分流、导入 checksum 校验。
  - **门禁先例**：`packctl tenant-scan` CI 强制多租户铁律（`docs/PLUGIN-AUTHORING.md` §1.1）；llm-doctor 有进程内真发模型调用先例（与 agent 会话同 wire 路径）。
  - **关联计划**：`plans/2026-11-10-llm-gateway与用量统计插件计划.md`（待执行，独立 worktree）——本计划 AI 链路走进程内 `ctx.llm`，llm-gateway 落地后自动受益，两计划无耦合冲突。

## 3. 访谈结论（已确认决策）

| 维度 | 结论 |
| --- | --- |
| 开放范围 | **全景查看 + 全部可编辑**：三层全部进工作室；上游 preset 段（plan-mode 等）编辑时标注「升级可能覆盖」风险 |
| 写权限 | **仅 admin 可写**，R3 两段式审批维持并扩展到全部条目；版本库/审计/导入校验沿用 T7 机制 |
| 注入架构 | **登记制 + 会话快照 + 写穿热生效**（用户裁定核心诉求：可编辑、不重启热生效、可回滚）；插件仍走官方 seam，但必须在工作室注册表登记元数据，packctl 门禁强制 |
| AI 能力 | **手动触发 + diff 预览 + R3 生效**：润色出建议稿、审核出问题清单，AI 产出永不直接生效；链路走进程内 `ctx.llm`（llm-doctor 先例） |
| 历史会话语义 | **会话粒度快照（严格）**：会话开启时快照 effective prompt，全程沿用；改提示词只影响之后新开会话；依赖 waterfall 会话区分（P0 spike，不支持则按 §4 降级） |
| 交付节奏 | **三期分期交付**，每期独立验收 gate；waterfall spike 放 P1 末尾 |
| 前端设计语言 | **严格遵循整体产品设计语言与风格**（用户 2026-11-11 追加）：延续 panel v3 设计语言 + DSH 官方语义令牌，全期硬约束，详见 §5.1 |
| 落点 | 新 worktree/分支（仓库惯例，参照 llm-gateway 计划）；不混入 `fix/access-tenant-bootstrap` 未提交改动 |

## 5. 范围

**做**：
- 生产挂载：`profiles/eterna-web/cordis.patch.yml` 加 prompt-studio insert 行（含 `TOGGLEABLE_PLUGINS` 启停登记，PLUGIN-AUTHORING §1.1 第 4 条）；
- 提示词注册表（Prompt Registry）：条目模型 = {id, 层(preset/domain/runtime), 来源插件/包, patch 定位, 当前值, 只读标志(全部可写→无只读，但带风险标注), 登记元数据}；三层存量全部登记；
- 写链路泛化：R3 审批规则从单 persona 扩为按条目/通配；写穿 configEditor 热生效；版本库/审计/回滚覆盖全部条目；
- 会话快照：会话开启时快照 effective prompt 入 DSH_HOME 存储；waterfall 回放（spike 通过后）；
- packctl 门禁：扫描 cordis.patch.yml 的 prompt 型 config 键 + `ctx.systemPrompt.section` 使用 + packs persona，未登记者 CI 拦截；
- AI 润色/审核：建议稿 + 问题清单 + diff 预览，R3 生效；
- 前端改造：StudioPage 从「persona 单条」改「注册表全景」（分组导航 + 编辑器 + 版本/diff + 审批卡 + AI 区），遵循 `--dsw-alias-*` 令牌与交互纪律（AGENTS.md 铁律）。

**不做**：
- 不 fork / 不改上游 dsh 源码（零内核改动铁律）；
- 不做租户级提示词覆盖层（已裁定 admin 全局单层）；
- 不做 AI 自动生效 / 保存前强制审核（已裁定手动触发）；
- embed 档挂载、llm-gateway 本体（另计划）；
- 不管理第三方模型供应商的系统提示词（只管本产品 agent 基座提示词面）。

### 5.1 前端设计语言约束（全期适用，用户 2026-11-11 追加）

**基线**：整体产品设计语言 = **panel v3 的 apple.com 风格**（大标题/大留白/hairline 分隔/胶囊按钮）+ DSH 官方语义令牌。工作室现有前端已合规（`packages/prompt-studio/src/client/styles.ts`：136 处 `--dsw-alias-*`、零硬编码色，注释明示对齐 panel v3）——本改造是**延续与扩展，不是引入新设计方言**。

1. **令牌铁律**（frontend-style v2 §1.1）：面板内 UI 颜色一律 `--dsw-alias-*` 官方语义令牌，深浅主题自动跟随产品壳；禁止字面色值（插件插画 artwork 固定渐变 SVG 为唯一豁免逻辑，容器/描边/文字仍走令牌）。新增颜色需求 = 先评估是否已有语义令牌，无则上报，不自造。
2. **形态铁律**：工作室维持 dsh 官方扩展点形态（`main` keyed 面板 + `sidebar.panellist` 入口，panel/llm-doctor/用量统计先例同构），不建独立页面；不造新导航，滚动/布局职责沿用现有 root 约定。
3. **交互一致**（frontend-style v2 §1.4）：主操作=主按钮、次操作=ghost 描边、破坏性（回滚/导入覆盖）=红字+两击确认；label 上置、聚焦光圈、错误/成功就地显示；同一卡资料类字段合并保存（脏检查驱动）；变更请求防重复点击；禁用原生 `confirm()/alert()`。
4. **可访问性与响应式**（§1.5/§1.6）：`lang="zh-CN"`、语义标题层级、`:focus-visible`、`prefers-reduced-motion` 降级、触控目标 ≥36px、640px 断点单列自适应。
5. **新组件先例对齐**：改版与新增组件（分组导航、条目详情、diff 视图、快照查看、AI 建议稿/审核报告卡）逐一对照 `packages/panel/src/client/` 与 `packages/access/src/client/` 的既有同类组件形态（卡片层级、字号阶梯、间距节奏、空态/加载态），不发明孤立样式。
6. **验收即设计走查**：每期 gate 的截图过审 = 深浅两主题 × 关键页面（全景列表/条目编辑/版本 diff/AI 报告），并按 `docs/design/frontend-style.md` §4 清单逐项自查附在 gate 证据中。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| waterfall 无法按会话区分（`AssembleContext` 无会话 id） | 严格版「历史会话沿用历史」不可达 | P0 spike 前置（T1.7）；降级路径已定（§4），出结论即报用户裁定，不空转 |
| patch 行重述写回碰上 profile 升级合并 | 编辑丢失/冲突 | 版本库可回滚兜底；编辑器展示条目来源行号；升级覆盖风险 UI 标注 |
| 上游插件 config 改后不热生效 | 「不重启」承诺部分落空 | T2.2 逐条目实测矩阵，如实标注生效半径；不造 restart 假象（README 数字实测可追溯铁律） |
| 编辑坏提示词导致组装失败 | 会话不可用 | 组装失败上游本就 fail-closed（不发格式错误提示词）；写前校验器（非空/UTF-8/64KB/红线锚点）逐条目执行 + 回滚通道 |
