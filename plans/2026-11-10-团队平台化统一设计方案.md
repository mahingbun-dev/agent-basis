## 1. 产品定位与愿景

**一句话**：把 EternaAgent 从「单人自部署 Agent 工具」升级为「可信小团队（≤20 人）共享单实例的团队 Agent 平台」——一次交付安全底盘、原生多模型能力、用量可观测、双层插件生态四根支柱。

| 支柱 | 回答的用户问题 | 来源计划 |
| --- | --- | --- |
| 安全底盘（隔离） | 「我们敢把一个实例给全团队用吗？」 | 隔离计划五条需求 |
| 模型能力（网关） | 「不运维 LiteLLM，三家模型差异能力还在吗？」 | LLM 计划 M1 |
| 用量可观测（统计） | 「Token 花在哪了？」 | LLM 计划 M2 |
| 插件生态（双层空间） | 「团队的创新怎么长出来、又怎么安全扩散？」 | 隔离计划需求④ + T7 |

四者缺一不可：没有安全底盘，其余一切在多用户下都是漏的；没有模型能力，平台没有开箱即用的核心体验；没有可观测，组织无法持续运营；没有生态路径，平台长不大。

## 3. 产品评估

### 3.1 角色与信任分级模型（本方案的评估主轴）

| 信任级 | 对象 | 闸门 | 逻辑 |
| --- | --- | --- | --- |
| 全信任 | 平台核心代码（内置/公共层插件） | 代码审查 + admin 启停 | 组织背书 |
| 用户自担 | 个人层插件 | **免审批**，仅本人加载（用户拍板，可信小团队前提） | 影响面=本人；试验田 |
| 组织背书 | 转内置插件 | 审批闸（个人发起→admin 审；admin 直转即时） | 扩散到全员才过审 |
| 组织资产 | 模型供应商 key / 网关配置 | **admin 可写、全员只读**（D1 拍板；key 值任何接口不回传，X1） | 全组织流量所系；透明可看防「黑箱配置」 |
| 组织资产 | 全局用量数据 | admin 可见全局/按用户；个人仅见本人 | 运营需要，最小暴露 |

这个分级是两份计划决策的统一表述，也是 X1 角色门的依据——原 LLM 计划缺了第四行，合并后补齐。

### 3.2 用户旅程（把全部交付物串成一条线）

1. **入职**：admin 建号 → 成员登录（门禁）→ 首开自动落座空会话（PR #4）→「添加工作区」只见**自己账号目录的目录树**（P1-T5，无路径输入框）。
2. **日常**：会话/工作区互不可见互不可开（P1-T1/T2）；bash/终端写边界=账号目录（P1-T3/T4）；`cd ../` 逃不出去。
3. **用模型**：会话内模型选择器按供应商分组，三家任选；思考流/多模态/联网开关原生可用（P2）；联网开关旁有属地计费中文提示；不再依赖外部 LiteLLM 服务。
4. **回顾**：打开用量面板看自己的 Token 活动热力图/趋势/模型占比（P3）；admin 切全局视图看团队大盘。
5. **成长**：成员写了个好用的个人插件 → 免审批装进自己目录、仅自己可用（P4-T6）→ 用出价值后发起「转内置」→ admin 收到站内审批提醒（P4-T7）→ 通过后全员可用、原件标记「已转内置」。
6. **离场**：admin 删除用户 → 登记行+账号目录+个人插件+用量派生数据**级联销毁**（P4-T8，含 X3）。

旅程无断点：每一站都由某根支柱承接，这是「合并为一份方案」的产品完整性证明。

### 5.1 静默执行纪律（v2 新增）

本方案按**无人值守连续执行**编写：所有任务自带验收判据（§6 各阶段准出门禁 + §8 测试执行方案），执行中不设人工确认点。仅以下事项不可静默、必须回到用户：

1. **rebuild 镜像 + 重部署生产**（两处：**PH 末一次**——生产事故 I2/I3 修复生效验证；**P4 末一次**——终验。纪律：不动运行中容器；日常验证在独立测试容器/本地 boot 完成）。
2. **`git push` 与 PR 创建/合并**（AGENTS.md：push 单独确认）。
3. **门禁连续两轮修复仍红**：止损上报（附 gate-summary 与失败证据），禁止无限重试或放宽判据。
4. **发现方案与仓库实况冲突**、需变更本方案设计决策时（先停后问，不得擅改口径）。

豁免规则：真连用例因供应商前置未满足（MiMo web_search 控制台开通、DeepSeek 联网 pro 档）允许**文档化豁免**——gate-summary.json 中该 case `verdict:"exempt"` + `exemption{reason, remedy, approvedBy:"用户"}`（详见门禁计划 §1.3），不静默跳过。

**顺序论证**：
- **P1 安全先行**（不与 P2 对调，D1 默认拍板）：G3 mux 缺口=当前任何人可读他人会话，而部署经 NAS 443 反代**公网可达**（PR #4 E2E 即走公网入口）——高危暴露面先堵；且 P2/P3 的新端点守卫、角色门都挂在 P1 扩好的守卫体系上。
- **P2/P3 先于 P4**：T6 是全案最重风险块（5–7 天、上游未组合路径），放后不阻塞任何前置；网关/统计以现有公共层机制落地，T6 对公共层「现状不动」，零返工。
- LiteLLM 退场（P2 末）与 landlock 预检（P1 内）先后动 `docker/entrypoint.sh`，序列化执行天然无冲突。

**统一估时**（R3 修正后）：P0 半天–1 天 ｜ P1 约 9–11 天 ｜ P2 约 6–9 天 ｜ P3 约 2–3 天 ｜ P4 约 10–13 天 ｜ **合计约 28–37 个工作日**（日历 6–8 周，含真连排队与修复轮次）。
