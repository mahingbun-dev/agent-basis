## 4. 未过项详情（如实标注）

### access 角色线：`packctl tenant-scan` exit 1

**记录的失败**【输入】——verify exit 0 之后，tenant-scan 崩溃退出 1，错误原文：

```
Job.run (node:internal/modules/esm/module_job:439:25)
    at async onImport.tracePromise.__proto__ (node:internal/modules/esm/loader:643:26)
    at async asyncRunEntryPointWithESMLoader (node:internal/modules/run_main:101:5) {
  errno: -2,
  code: 'ENOENT',
  syscall: 'scandir',
  path: '/Users/sunny/.zcode/workspace/1794762961511-29e33e2a-233c-4894-81a4-71a6894ae22f/packages'
}
```

**成因定位**（本报告【实测】，三步）：

1. `cmdTenantScan` 以 **`io.cwd` 为 repoRoot** 调 `tenantScan(io.cwd)`（`tools/packctl/src/cli.ts:116-117`）；
2. `tenantScan` 第一步即 `readdirSync(join(repoRoot, 'packages'))`（`tools/packctl/src/tenant.ts:196-198`）；
3. 该 cwd（zcode 工作区 `/Users/sunny/.zcode/workspace/1794762961511-…`）下**并无 `packages/` 目录**（【实测】`ls` 该目录仅 `chat-demo`、`dsh-superagent-prototype`、`fused-arch.excalidraw` 三项）→ `scandir` ENOENT、进程崩溃 exit 1。

**补充复核**（本报告【实测】重跑）：在仓根 `/Users/sunny/code/agent-basis` 执行 `node tools/packctl/bin/packctl.mjs tenant-scan` → 输出 `tenant-scan: 0 finding(s)`，**exit 0**。

**判定（两说并列，不擅自改判）**：
- 按输入 JSON，该线 `ok:false`，**维持未过**——门禁在门禁命令的实际执行环境下确实退出了 1；
- 补充实测表明：同一命令在仓根正确 cwd 下 0 finding 通过，失败**归因于运行位置（cwd 指向无 packages/ 的 zcode 工作区）而非检查发现隔离铁律违规**。是否据此复判该线为过，属门禁口径裁决，留待下轮（或门禁所有者）拍板；本报告仅登记事实。
