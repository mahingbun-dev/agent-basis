## 0. 一句话结论

**以 `dsh-v0.2.2-rc.5` 为唯一目标版本，一次性完成依赖族升级、profile/preset 重放、
v1 线入库、MCP 两层、office/chat-import/ACP/terminal/品牌首页能力落地；
生产数据从 named volume 迁到 `$HOME/eterna-data/<instance>` 整树单挂载；
所有面向租户的能力按「会话属主」收口，ACP 只对运维本机开放。**

这不是一次 `git merge`：本仓与上游无共同 git 历史，合并 = **L1 依赖族升级 +
L2 上游派生文件重放 + L3 新能力选择性采纳**（47 §0.1）。

## 1. 目标、范围与非目标

### 1.1 目标

1. 全仓 `@deepseek-ai/dsh-*` / cordis / loader / include 统一到 `0.2.2-rc.5` 代，
   消除当前 alpha.2 / alpha.3 / rc.1 混族。
2. 修复 rc.5 的三个确定性破坏面：`LlmError` 构造器（H1）、subagent API（H2）、
   客户端跨 release 拒收（H8）。
3. 把上游新能力按产品边界落地：agent-team、office、MCP 两层、chat-import、
   实验 bundle 默认集、hero 品牌浮层、terminal-panel、ACP。
4. v1 `@core/*` / `@basis/*` 线进入本分支，与产品线同仓但**不同运行入口**。
5. 容器数据改为宿主 `$HOME/eterna-data/<instance>` 整树单挂载，`/data` 语义不变。
6. 交付可复现的门禁、回滚与测试证据，rc.5 预发布按 `docs/upgrade-gate.md` §7 例外上生产。

### 1.2 范围

| 层 | 内容 |
|---|---|
| L1 依赖 | catalog 20 个 `dsh-*`、cordis 4.1.0、cosmokit 1.9.0、loader/include、peer 补齐 |
| L2 派生 | 5 份 profile/preset 模板、bundle 行集、prompt-studio 锚点、brand skills、compaction fork、`core/cordis` vendor |
| L3 能力 | B1–B20（见 §4/§5）；A1–A11 必做适配；T3/T5 观察、T6 关闭 |
| 部署 | Dockerfile、entrypoint、compose（web/super/acp）、反代、数据根 |
| 质量 | 全仓 verify、双形态 boot、access 漂移、业务 E2E、双主题三视口截图、数据浸泡 |

### 1.3 非目标（本轮不做）

- 不合并上游 telemetry / 产品分析 / DeepSeek 账号 / session-log 上传（C1–C3）。
- 不采用官方品牌 UI `ui-brand-official`（C4）；品牌走 `@eterna/brand`。
- 不做 Desktop 专属件、LiveShare、CUA（C8；平台/外部依赖不满足）。
- 不整体替换本品 compaction / access（C10/C11）。
- 不把 WebWorker 当产品运行时（T6 已拍板不产品化）。
- 不做容器 root/UID 重映射、不做数据加密、不支持 NFS/SMB 数据根（48 §2.2）。
- 不把 ACP 暴露给终端用户或映射端口。

## 3. 总体架构

### 3.1 仓库与运行入口

```text
agent-basis (pnpm workspace)
├── packages/@eterna/*        # 产品 L1 插件（Host + Client 双半边）
├── tools/*, packs/*, market/*# 领域包/工具/市场
├── docker/profile/*          # eterna-web / eterna-super / eterna-acp 模板
├── core/{cordis,contracts,runtime}   # v1 内核（B11 入库）
├── packages/{system-prompt,...}      # v1 @basis/* 六插件（与产品同仓、异入口）
├── basis.yml                 # v1 最小集清单（不进 Docker）
└── deploy/, docker-compose*.yml

产品入口（生产）:
  dsh --profile eterna-web | eterna-super | eterna-acp
  └─ bundles: base + web-app + 产品默认集（+ terminal）
     └─ 产品扩展点：settings.section / conversation.* / plugins.tab / 守卫路由

v1 入口（仅仓库/测试）:
  node core/runtime/bin/basis.mjs chat --bundle basis.yml   # EOF 退出，仅装载
```

### 3.2 请求与安全边界

```text
浏览器 / IDE(ACP)
   │
   ├─ HTTP /api/*  ──► access 路由门（cookie→用户→ownership→钳制）
   │                      ├─ settings 命名空间 gate（llm-pi-ai / mcp-manager）
   │                      ├─ mcp-personal 路由（本人 CRUD）
   │                      └─ chat-import 路由（登录 + workspaceOwner + 流式记账）
   ├─ WS mux /api/remote.mux ──► access mux 守卫（按资源 kind/sessionId 属主）
   │                      ├─ terminal/* 9 动作
   │                      └─ 其它 session 资源动作
   └─ ACP stdio（无端口，仅运维本机）──► eterna-acp profile
```

**铁律**：任何面向租户的路由/流动作，都必须由 `eterna-access` 拥有并登记；
插件不得自注册租户路由（`packctl tenant-scan` 强制）。ACP 是受信控制器，不做租户隔离，
因此只允许本机运维启动。

### 3.3 数据面

```text
$HOME/eterna-data/                 # P0-3；0700；不纳 git
├── super/  ──bind──► /data        # 生产 super 实例（一个实例一个根）
├── base/   ──bind──► /data        # base 形态（并行测试用）
├── test-<date>/                    # 测试实例（独立端口）
├── backups/                        # 冷备，不挂进容器
└── exports/                        # 人工导出，不挂进容器
```

容器内路径不变：`DSH_HOME=/data`、`working_dir=/data`、`DSH_AGENTS_HOME=/data/agents`。
详见 48。

3. **H1**：`LlmError` 构造器收窄；`compaction/summarizer.ts`、`memory/extraction.ts`、

4. **H2**：tasks `background.ts` 改 `waitForTreeWork` / `listDescendants` /

7. **H6**：profile 行序定稿后重算 prompt-studio 10 个 registry 锚 + 23 个 ledger 锚。

### 5.2 Profile / preset / bundle（B1、B18、B20）

  `cordis.super.patch.yml.template` + 新增 `cordis.acp.patch.yml.template`。
- bundle 清单：`docker/profile/package.json` 的 `dsh.profile.bundles` 改为
  `[base, web-app, chat-import, session-search, plugin-market, terminal-bundle]`；
  ACP 用 `package.acp.json`（只 `[base, acp-app]`）。
- 行处理：agent-team 系、ui-file-actions/ui-context-menu 补 patch；
  `mcp-manager` 只覆写 `config.servers`（`name/inject` 沿用 web-app）；
  `office-kit`/`skill-office` 由 web-app 自带、不重复 insert；chat-import 进

  cordis 补 persona 第三行/`interrupt:false`。

### 5.3 access / 租户安全（B12）

- `mux-drift` / `mux-peer-drift` 对账 rc.5 新方法表；差集为空。
- `terminal/*` 9 动作入守卫（B20）；`workspaceFiles/search`、`terminal/watch` 归位。
- Settings 命名空间 gate 扩展到 `mcp-manager`（系统层写/读/管理动作 admin-only）。
- chat-import 路由门（B16）与 mcp-personal 路由（B14）都登记在 access。
- 所有拒绝审计 `tenant/denied`，成功审计不含内容/密钥。

### 5.4 MCP 两层（B14，v6/v7）

| 层 | 管理者 | 存储 | 可见范围 | 传输 |
|---|---|---|---|---|
| 系统层 | admin | profile `mcp-manager.config.servers` | 全 Host | stdio/HTTP，admin 决定 |
| 个人层 | 每个用户 | `/data/access` 的 `mcp_personal_server`/`mcp_personal_secret` | 仅本人 Agent scope | stdio 仅管理员目录；HTTP `http:`/`https:` 任意 host（白名单暂关，元数据拒） |

个人层关键机制：

- `agent/created` 时按 `sessionOwner` 取用户条目，`createScope(ctx, agent)` 内挂
  `dsh-mcp-client`，`serverName='p<uid>_<slug>'`；
- `tools/pre-execute` + `tools/execute` 双层按 session 属主校验（同用户子代理放行，
  跨用户 deny）；监听必须在 Host root 以 `{global:true}` 安装，不能被 scope 过滤；
- **删除/禁用 → 立即 dispose 该用户 live 会话的个人 scope（工具当场消失）**；
  **登出 → dispose 该用户全部 scope**；新增/更新 → 新会话生效（live 会话保持旧配置
  直至关闭）；会话关闭/宿主卸载兜底 dispose；
- stdio 自填 `command` 400；HTTP 允许 localhost/私网，云元数据地址拒绝；
  `personalHttpHosts` 空=全放行、非空=白名单（未来收紧开关）；
- 限额：8 条/4 连接、8s 启动、60s 调用、reconnect 3 次、256KB 配置；
- 密钥 AES-256-GCM，日志/审计/错误 redacted。

### 5.5 office（B15）

- `office-kit`（WASM 转换）+ `tool-office` + `skill-office`；standard/ptc preset

- 镜像补 Noto CJK/Liberation/DejaVu 字体与 `python-docx/openpyxl/python-pptx`；

### 5.6 chat-import（B16）

- 路由 `/api/deepseek-chat-import/archive?workspaceId=…` 由 access `admit` 门保护：
  未登录 401；跨用户 workspaceId 403；workspaceOwner 校验。
- NDJSON pass-through `TransformStream` 解析最终 outcome 行的
  `outcome.value.sessionIds` → `recordSession`；
  失败/取消用 `workspaceRegistry.sessionIds` 对账补记账。
- 保留上游 owner 检查作纵深；反代 `client_max_body_size ≥ 512m`；
  512MiB 驻留内存测试；UI 先上游后 v4 审计。

### 5.7 ACP（B17）

- 独立 `eterna-acp` profile（`package.acp.json` = base + acp-app）与独立 service；
  `profiles:["acp"]`、`stdin_open:true`、`tty:false`、无端口、同 `/data`。
- entrypoint `ETERNA_FORM=acp`：entrypoint 自身日志逐条写 stderr（**禁止全局
  `exec 1>&2`**，否则 dsh 的 JSON-RPC stdout 也被改道）；不启动 relay/web；
  `flock` profile 渲染锁；最后 `exec dsh --profile eterna-acp`。
- 挂 governance/audit/egress 三行；不挂 memory/knowledge/channels；
  模型走 `mimo/mimo-v2.6-pro`；`session/request_permission` 承接治理 ask。
- 受信控制器：可指定容器内 cwd/MCP 命令/env；只允许运维本机，不暴露端口。

### 5.8 实验 bundle 默认化（B18）

## 6. 安全与租户隔离矩阵

| 能力/动作 | admin | 普通用户 A | 普通用户 B | ACP（运维） |
|---|---|---|---|---|
| 全局 MCP 服务器增删/`watch/restart/probe` | ✅ | ❌ 403/deny | ❌ | ❌（ACP 不挂 mcp-manager 全局表） |
| 个人 MCP 条目 CRUD | ✅（自己的） | ✅（自己的） | ✅（自己的） | ❌ |

| terminal 工具/侧栏 | ✅ | 仅 A 的会话 | 仅 B 的会话 | ❌ |
| `terminal/*` 远程动作 | 仅自己的会话 | 仅 A 的 sessionId | 仅 B 的 sessionId | ❌ |
| chat-import 上传 | ✅ | 仅 A 的 workspace | 仅 B 的 workspace | ❌ |
| 插件市场写/安装 | ✅ | ❌ | ❌ | ❌ |
| 设置-账号资料/密码 | 自己的 | 自己的 | 自己的 | ❌ |

## 8. 失败域与回滚

| 失败域 | 表现 | 回滚 |
|---|---|---|
| 依赖/类型 | 全仓 verify 红 | 还原版本号+lockfile，回到旧镜像 |
| profile/bundle | boot 失败/插件丢失 | 保留旧 manifest 备份；恢复 `.upgrade-*` 留痕文件 |
| 客户端 bundle | 页面空白 | 重建 10 包；旧镜像回滚 |
| MCP 个人层 | 跨租户/工具泄漏 | `personal.enabled=false` kill switch；回滚镜像 |
| chat-import | 会话无主/跨租户 | 关闭 bundle 行；回滚；对账脚本补记账 |
| ACP | stdout 污染/端口暴露 | 停 acp service；不影响 web |
| 数据迁移 | SQLite 损坏/WAL 错 | 停容器 → 旧卷/冷备恢复 → 旧镜像启动 |
| terminal | 资源耗尽 | 从 profile 移除 terminal bundle（需重建 profile） |
| hero | 首页不可用 | 禁 hero slot（`hero=false`）/回滚 brand client |

**单段升级无中间版本**：Phase 1 未全绿不得进 Phase 3；生产回滚只有旧镜像 + 冷备两条路。
