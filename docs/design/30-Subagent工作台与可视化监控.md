# 30 - Subagent 工作台与可视化监控

> 状态：**设计定稿（§7 四问已于 2026-11-17 第三轮全部拍板）**。本文落实 2026-11-17 新增范围：superagent 产品化的前端可视化要求——工作监控、图形化信息流实时监控、日志监控、评测监控，合成一个 **subagent 工作台**。
> 决策原文：整个 superagent 产品化，需要在前端存在可视化的工作监控、图形化的信息流实时监控、日志监控、评测监控等。要做一个 subagent 工作台。前端样式设计调用设计 skill，基于当前产品设计语言，用户交互体验优先，输出原型图后**严格按照原型图开发**。
> 关联：`24-主动工作体系融合设计`（§7.2 五角色、§5.5 附加项 audit-as-trace）、`27-执行者模型与冲突解决`（D2 冲突三指标、信息流即其静态架构的活化）、`28-上下文策略`（路由金集）、`docs/design/frontend-style.md`、`design-tokens.md`、`iconography.md`、`packages/panel`、`packages/access`、`tools/dsh-evals`

## 0. 一句话结论

工作台 = **panel 的扩展**（keyed panel 先例已有）+ workspace slots 深视图，**五视图一检查器**；数据全部来自既有或 P1 已规划的事件面（Engine DomainEvents、audit trace、dsh-evals、observe），传输统一 SSE（客户端解码器照搬 chat-demo 的 WHATWG 规范实现）；UI 严守 AGENTS.md 铁律与**原型先行流程**。

## 1. 定位与用户

| 角色（24 §7.2） | 用工作台做什么 | 主要视图 |
|---|---|---|
| 审批人/主管 | 看"等谁的"清单、答复 Attention | 工作监控 |
| 平台管理员 | 看系统健康、负载、异常流 | 工作监控 · 信息流实时图 · 日志 |
| 领域专家 | 看金集趋势、调包 | 评测监控 |
| 审计/合规 | 查工单全链路 | 日志监控 |
| 发起人 | 看自己的单到哪步了 | 工作监控（仅本 realm 自己的工单） |

**面板只显示需要人的东西**（superagent philosophy 纪律）：健康态不占版面。

## 2. 五视图 + worker 检查器

| # | 视图 | 内容 | 数据源（现状） |
|---|---|---|---|
| 1 | **工作监控** | 工单按阶段看板（`person/*`、`working/queued`、`idle` 分列）+ 冲突三指标（attach 次数 / duplicate 比例 / 插队次数，27 号 D2） | tasks Engine（P1 产出） |
| 2 | **信息流实时图** | Trigger→Thread→Eval→Decision→Ticket→Assignment→Worker→Report→Outbox **活图**，节点状态实时跳动、卡点高亮 | Engine 的 11 个 DomainEvents（superagent 已枚举，移植保留）经 SSE 推送 |
| 3 | **日志监控** | 按工单聚合的 audit trace（Trigger→候选卡→Decision 理由→委派→报告→门禁全链）+ worker 会话日志，可过滤检索 | audit-as-trace（24 §5.5 附加项）+ 上游 session 事件 |
| 4 | **评测监控** | 金集通过率趋势、路由金集衰减（28 §5）、漂移检测曲线 | dsh-evals 结果 + observe（漂移已有） |
| 5 | **worker 检查器** | 单 worker 深视图：子代理树（27 号三层结构的实况）、运行中 jobs、工具调用历史、上下文占用 %、成本累计 | 上游 session/jobs 事件 + R1 预算数据 |

### 2.1 旗舰视图：信息流实时图

它把 27 号那张静态权力结构图**变成活的**。试点期价值最大：让人看见系统在干什么、卡在哪（哪个节点变黄 = 哪类事在等人）。节点即领域对象，边即 DomainEvents；"卡点高亮"= `person/*` 阶段的工单在图上以警示色驻留。支持**单工单回放**：选中工单在图上重放其事件序列（§7-2 拍板）。渲染用 **Canvas**（§7-1 拍板），配套交互与 a11y 要求见 §7。

## 3. 数据与传输

| 项 | 方案 |
|---|---|
| 服务端 | 管理面新增 SSE 流（经 access 鉴权——**不是** superagent 的 loopback-only），订阅 Engine DomainEvents + session 事件 + 指标心跳 |
| 客户端 | SSE 解码器照搬 chat-demo `sse.ts`（WHATWG 规范实现：跨 chunk 边界 / CRLF 半个 / 多字节截断三陷阱已解） |
| 快照 + 增量 | 连接时先推全量快照（当前工单/线程/worker 状态），再推增量事件；断线重连以 `Last-Event-ID` 续 |
| 频控 | 事件聚合窗口 **200ms 合批**（§7-2 拍板），避免高频 report 事件打爆渲染 |

## 4. UI 落点与铁律

1. **不建独立页面**：工作台 = `packages/panel` 扩展（keyed main panel 先例）；工单/worker 深视图走 workspace slots；
2. **设计令牌**：一律 `--et-*`（经 `--dsw-alias-*` 桥接），禁字面色值；图标走 `@eterna/ui/icons`；
3. **中文 UI** + a11y（语义标题、focus 光圈、`prefers-reduced-motion`）+ 响应式 1100/760/640；
4. **深浅双主题**截图进 PR；
5. **多租户与角色**：工作台数据按 access realm 钳制——普通用户仅自己的工单；**审批人（新角色，§7-3 拍板）见全租户待人项**；管理员全量。


## 7. 拍板记录（2026-11-17 第三轮，四问全部落定）

| # | 决定 | 实施含义 |
|---|---|---|
| 1 | **信息流图渲染 = Canvas** | 性能优先。配套三件事：① hover / 点击 / 拖拽交互手写（无 DOM 免费午餐）；② 主题令牌渲染时经 `getComputedStyle` 读取 `--et-*`（画布不吃 CSS，双主题切换需重绘）；③ **a11y 补偿**：Canvas 无 DOM 可读——旁挂一个可键盘导航的等价列表视图（工单/节点清单），屏幕阅读器与键盘用户走列表不走画布 |
| 2 | **实时语义 = 200ms 合批 + 暂停 + 单工单回放** | 回放：选中工单 → 图上重放其事件序列（数据源 audit trace，成本低，对审计演示有说服力）；**全局时间轴回放不做**（成本高、价值边际） |
| 3 | **可见性 = access 新增「审批人」角色（方案 b）** | 审批人见全租户待人项；普通用户仅自己的；管理员全量。access 改动：用户表角色字段 + mux 过滤 + 用户管理 UI 三处；**B2 领域专家角色后续共用此机制**（一次立住角色模型） |
| 4 | **日志 = 默认摘要行 + 展开全文 + PII 正则** | 摘要行：工具名 / 参数摘要 / 结果状态 / 耗时；展开全文过 governance `pii.ts` 可插拔正则；原始全文已在 audit NDJSON，展示层只过滤不删改 |
