## 0. 摘要与决策表

压缩系统在产品中的定位：**会话连续性引擎**——它不是省 token 的可选优化，而是长会话产品的可用性底座（业界共识：OpenAI 官方"compaction 是长程默认原语，不是紧急兜底"）。与记忆系统的分界沿用 17/18 号拍板：**compact 维持当前 session 连续性，Memory 保存跨 session 可复用事实**。

| 决策 | 结论 | 依据（20 号） |
|---|---|---|
| D1 触发体系 | 保留现阈值（0.8/65536/0.16），新增**陈旧清理层**（更低阈值、确定性、零模型成本）与 **rapid-refill 熔断**；四路径触发不变 | §3.1：分层+熔断是四件套 |
| D2 压缩路线 | 只做 LLM 结构化摘要 + 确定性截断/清理两层；**不做** token 删除式、soft-token 式 | §2.3 学术裁定（工件场景不适用/不可审计） |
| D3 保真红线 | 摘要永远不是唯一副本（durable log 全留）；结构校验拒收空/残摘要；用户指令与安全约束逐字保留 | §2.3/§3.3 |
| D4 评估纪律 | 压缩比不是质量指标；golden 回归（关键事实召回/误报率）是 prompt 与阈值改动的前置门禁 | §3.4（Factory/KEEP-Bench） |
| D5 用户可见 | 压缩可感知、可控制、可回溯三件套（会话公告 / 设置分区 / checkpoint 视图），消灭静默压缩 | §2.1（Claude Code issue #21925 教训） |
| D6 记忆联动 | 压缩摘要进记忆必须走 `source=compaction` → 强制 pending 审批（C3 投毒通道闸门）；记忆索引为 prompt section，与压缩无遮蔽交互（20 号 G7 修正） | §2.4 + 19 号 T2 已实现 |

## 1. 产品定位

### 1.1 在产品架构中的位置

```
用户会话（eterna-web / eterna-embed）
 ├─ 会话内连续性 ← 【本设计：压缩系统】（pruner 截断 → 陈旧清理 → 结构化摘要 → 溢出兜底）
 ├─ 跨会话事实 ← 记忆系统（17/18/19 号，两层作用域+审批）
 └─ 原始事实 ← durable session log（永不删，回放/审计/重放的事实源）
```

三层各司其职：压缩负责"模型此刻能看到什么"，记忆负责"跨会话该记住什么"，durable log 负责"到底发生过什么"。任何一层的输出都不冒充其他层的事实源——尤其压缩摘要不得成为记忆的一手来源（审批闸门兜底）。

### 1.2 服务对象

- **最终用户**（多租户下的每个租户）：长会话不断线、上下文不丢关键信息、成本可预期。
- **平台运营**（admin）：压缩行为可观测、可配置、异常（rapid-refill、连续失败）可发现。
- **下游系统**（记忆/审计）：可靠的压缩事件与 checkpoint 结构。

## 2. 设计原则（五条，全部有调研证据背书）

1. **可逆性优先**：durable log 全保留 + "路径即引用"。被遮蔽内容永远可回读（Manus"文件系统是终极上下文"、Amp"原线程永不删"）。
2. **确定性优先于模型**：能靠截断/清理解决的不调模型（Anthropic"先清旧工具结果，再考虑摘要"；ZCode 五层递进）。模型调用是压缩里最贵、最慢、唯一可能注入幻觉的一环。
3. **质量门槛前置**：压缩失败优于压缩损坏——空摘要/残摘要拒收重试；rapid-refill 报警停机；宁可不压，不压坏（Anthropic 警告"过度激进压缩丢失关键细节"）。
4. **缓存是第一成本指标**：任何压缩动作必须考虑 prompt cache 前缀影响；清理要"一次清够"（clear_at_least 思想），杜绝碎片化失效（Manus：cache 命中率是生产 agent 第一指标）。
5. **用户可见可控**：压缩对用户不是黑盒——何时发生、释放多少、保留了什么、哪里能看，全部可感知（Claude Code 静默压缩破坏在途工作是一票真实差评）。

## 3. 产品能力设计（C1–C6）

### C1 分层压缩策略（内部定型，用户无感）

产品内部策略定型为**四层递进**，用户侧无感知（这是"引擎"，不是"功能"）：

| 层 | 触发 | 动作 | 成本 |
|---|---|---|---|
| L1 落地截断 | 每条工具结果落地时（>8192 字符） | head 4096 + tail 1024 + 截断标记（现有 pruner） | 零 |
| L2 陈旧清理 | 压力达阈值 ~0.7 档（新增） | 旧工具结果组整组换占位符，保留最近 N 组、错误结果不清 | 零（确定性） |
| L3 结构化摘要 | 压力达阈值 0.8 档（现有） | 8 段 checkpoint 摘要替换遮蔽段，尾段 16% 原文保留 | 一次 LLM 调用（KV-cache 复用） |
| L4 溢出兜底 | provider 报 context overflow（现有） | pruner → 强制压缩 → 重试一次 | 兜底 |

配套熔断：压缩后 3 步内再次触发、连续 3 次 → 显式报警并停止自动压缩（防"压缩-填满-压缩"循环烧钱）。

### C2 压缩可感知（会话内）

- **压缩中状态**：摘要调用进行时，会话状态区显示"正在压缩上下文…"（复用现有 maintenance/bracket 状态面）——防止用户把压缩延迟误读为"卡死"（对齐本产品"会话挂起=审批未决"的既有教训：看不见的状态=故障）。
- **压缩完成公告**：checkpoint 落地后，会话流插入轻量系统提示行（中文）：
  > 上下文已压缩：释放约 N token，最近对话与任务进展保留完整。查看摘要
  点击跳转 C4 的 checkpoint 视图。占位为单行非阻塞提示，不打断对话流。
- **熔断报警**：rapid-refill 触发时会话内显示警告行 + admin 观测面计数（见 C5）。

### C3 压缩可控制（设置分区）

扩展现有「上下文压缩」设置分区（`settings.section`，样板 `packages/compaction/src/client/index.tsx`）：

| 控件 | 形态 | 默认 |
|---|---|---|
| 自动压缩开关 | 开关（现有 auto） | 开 |
| 触发时机 | 三档单选：更早（0.7）/ 标准（0.8）/ 更晚（0.9） | 标准 |
| 保留预算 | 滑杆（retainRatio 8%–24%，展示为"保留最近对话量"） | 16% |
| 陈旧内容清理 | 开关（L2 层） | 开 |
| 摘要模型 | 只读展示当前摘要所用模型（运营配置，用户不可改） | 会话模型 |

交互纪律：合并保存+脏检查、单按钮；变更请求防重复点击；文案中文、走 `--et-*` 令牌、深浅双主题。运营级参数（摘要模型路由、熔断参数、L2 阈值细节）不暴露给最终用户，走 admin 配置面。

### C4 压缩可回溯（checkpoint 视图）

panel 扩展（main 面板，复用 `packages/panel` 与 SRC 网关先例）：

- **checkpoint 列表**：本会话历次压缩的时间、释放量、摘要模型。
- **摘要正文查看**：8 段结构化渲染（只读）。
- **遮蔽范围与原文入口**：显示被遮蔽的消息区间；"查看原始记录"跳转 durable log 回放视图（已有审计/回放基础）。这是本产品相对 Claude Code/Codex 的差异化卖点——**压缩可审计**。

### C5 质量红线（内部机制，异常对用户/admin 可见）

- 摘要落盘前结构校验：8 段标题齐备、关键段（任务意图/当前工作）非空，否则按现有重试链重试，最终失败则放弃本次压缩并记录（压缩失败优于压缩损坏）。
- 误报红线：golden 评估中摘要出现原文无依据的断言 = 硬红线，禁止合入。
- 观测面（admin 统计扩展）：压缩次数/延迟 p50/p95、L2 清理回收量、rapid-refill 计数、摘要模型与用量、（接入 cache-guard 后）压缩动作的前缀失效影响。

### C6 记忆联动（与 17/18/19 的协议）

产品协议三条（实现细节在 22 号 C10）：

1. **压缩摘要进记忆只走审批通道**：来源标记 `source=compaction` → 强制 pending（19 号 T2 已实现该判定），审批卡片显示"来自压缩摘要"标记，用户批准才可被检索。依据：C3 投毒通道（压缩摘要把污染内容固化）+ 83% 压缩相关失败源于无依据摘要条目。
2. **记忆索引不受压缩影响**：索引是 prompt section（每次请求动态组装），不在会话表面——20 号 G7 的"索引被遮蔽风险"经代码核实不成立，无需重公告机制。
3. **职责单向**：压缩不读记忆、不依赖记忆服务在场（compaction 包独立部署时零记忆依赖）；记忆整固（M-M2）读 session log 时自然看到 checkpoint 节点，按规则 1 分类。

## 4. 策略定型速览（产品规格口径）

| 维度 | 定型 | 不做 |
|---|---|---|
| 触发 | L2@~0.7 / L3@0.8（有效窗口公式，预留输出+headroom）/ L4 兜底 / 手动 `/compact` | 条数/时间触发；调低于 0.7（过早压缩有延迟代价） |
| 摘要 | 8 段结构化模板 + 增量合并旧 checkpoint + 保留尾段时间线声明 + KV-cache 复用调用 | 整体重写式摘要（Gemini CLI 式）；token 删除/soft 路线 |
| 保留 | 尾段 16% 预算原文；system 头永不出压缩区；tool 对不拆 | 无保留全量摘要（Amp handoff 之外的场景） |
| 校验 | shrink 收敛 + 结构完整 + golden 回归门槛 | 压缩比目标 |
| 评估 | 关键事实召回 ≥90%、用户指令逐字召回 100%、误报 = 0、续跑完成率差 ≤10% | —— |

## 5. 与记忆系统的产品协同（时序）

```
会话进行中：
  压力达 0.7 → L2 清理（无感知）
  压力达 0.8 → L3 摘要 → 会话公告（C2）→ checkpoint 落 durable log
会话结束（M-M2 上线后）：
  整固 job 扫 session log → 识别 checkpoint 节点 → 提案 source=compaction → pending
用户审批队列（M-M2 T9）：
  「来自压缩摘要」标记的提案 → 批准 → 进入可检索记忆
```

压缩与记忆互不阻塞：压缩永不等待记忆服务；记忆缺席时压缩行为完全不变。

## 6. 多租户与合规

- 压缩配置已按租户隔离（`$DSH_HOME` 语义 + overrides 文件）；新增配置同边界。
- C11 附件重读（若实施）的文件访问严格限制在当前 workspace 内，路径逃逸拒绝（tenant-scan CI 断言）。
- 摘要内容不外发：摘要调用复用会话自身 provider 路由，凭据纪律沿用现有 llm seam（19a S-4：purpose 封闭联合，不自造调用类）。
- durable log 中的压缩记录遵守现有审计/egress 规则，无新增出网面。

## 7. 非目标（明确不做）

1. envelope（system prompt / tools 定义）压缩——上游 dsh-compaction 明示约束。
2. 面向模型的压缩工具（模型主动请求压缩）——上游延期项，跟踪 seam 开放，不自研绕过。
3. token 删除式（LLMLingua 类）与 soft-token 式压缩——学术裁定对结构化工件场景不适用/不可审计。
4. 全局/跨租户压缩策略共享——压缩配置是租户级，无全局层（对齐 18 号 org 禁用决议的精神）。
5. 压缩比作为产品 KPI。

## 8. 差异化定位（对外叙事）

| 对比 | Claude Code / Codex | 本产品 |
|---|---|---|
| 可审计性 | 摘要后历史对模型不可达（Codex 服务端还是加密 blob） | durable log 全留 + checkpoint 视图 + 原文回读入口 |
| 记忆安全 | 压缩摘要直接进 auto memory（C3 投毒通道敞开） | source=compaction 强制人工审批 |
| 多租户 | 单用户工具 | 租户级配置面 + admin 观测 |
| 质量纪律 | 阈值/模板黑盒 | golden 回归门槛 + 结构校验红线 |
