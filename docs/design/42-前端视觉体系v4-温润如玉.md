## 0. 为什么要换掉 Webflow

v3 选 Webflow 的理由是"收敛四套并存的语言"，它确实做到了统一。但三年下来它把产品
推向了另一个方向：**冷白 + 电光蓝 + 4px 锐角 + hairline 分隔**，是工具站的语言，
不是"方寸灵台"的语言。实测问题：

| 现象 | 根因 |
| --- | --- |
| 每个面板读起来像后台表格 | 4px 圆角 + 1px 硬边框把所有容器压平，层级只能靠线 |
| 信息靠长句承载，界面越长越像说明书 | 没有把状态、过程、比例做成形状的词汇表 |
| 深色主题发灰、发脏 | 纯中性灰阶（#080808/#101010）在 OLED 上塌陷，无温度 |
| 强调色被稀释 | 电光蓝同时承担链接、按钮、焦点、选中，一屏出现 5 次以上 |

v4 的目标不是"更好看的后台"，而是**把 agent 的劳动过程变成可读的东西**。

## 1. 设计立场

**温润如玉**不是加圆角、加阴影，而是三条可执行的约束：

1. **玉是暖的**：全色阶带暖底，没有冷灰。纯白与纯黑都不出现。
2. **玉是层层相套的**：容器有大弧，里面的东西弧更小，且**弧是同心收的**——
   子元素圆角 = 父容器圆角 − 内边距。这条规则让"嵌套"看起来像一块被打磨过的
   料子，而不是套娃。
3. **玉是含着光的**：材质感来自 1px 内高光（斜面）+ 暖调多层柔影，
   不来自渐变、玻璃、发光。**禁止** backdrop-filter、装饰性渐变、彩色光晕。

一句方向：

> 为掌管任务、审批与知识的团队设计企业 Agent 工作台，采用"玉质器物"的视觉语言，
> 以**同心弧 + 斜面高光 + 轨迹转译**为设计突破点。

### 1.1 必须保留

- 产品身份：恒灵 / EternaAgent 名称与闪电标；"方寸灵台，运筹万里"叙事。
- 全部功能、信息与交互语义（两击确认、脏检查合并保存、`no-store`、审计口径）。
- 设置类功能=设置弹窗分区；UI 走 `@eterna/ui` 令牌；图标走 `@eterna/ui/icons`。
- 双主题（应用内跟随宿主、独立页跟随系统）。
- 中文界面文案与术语表（工单、卡点、等人、审批队列、循环轨迹…）。

### 1.2 可以重构

布局节奏、信息密度、容器层级、状态表达方式、图形词汇、动效、字体。

### 1.3 最大的平庸来源

**把 agent 的运行事实写成句子。** 现在"等人 12 分钟""上下文 68%""3 个工具失败"
都是文字；它们应该是珠、环、条的形状。本次重设计的核心工作量在这里，不在配色。

### 2.3 语义色

| 令牌 | 浅色 | 深色 | 语义 |
| --- | --- | --- | --- |
| `--et-success` | `#2d7a55` | `#6cc294` | 完成、通过、绿线 |
| `--et-warn` | `#94661c` | `#dfae62` | 等人、卡点、需拍板 |
| `--et-danger` | `#a63d2e` | `#e08a7b` | 失败、拒绝、破坏性 |

语义色**必须配文字或形状**，不得只靠颜色区分。语义色不做大面积底色（最多 8%

### 2.4 图形专用色（不进 UI 文案层）

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--et-jade` | `#3f7d6a` | `#5f9b86` | 图表第二序列、珠链"已完成" |
| `--et-sand` | `#c2a179` | `#a98a63` | 图表第三序列、时间轴刻度 |

只用来说明数据，不用于按钮、链接、状态。

### 2.5 允许的材质（唯一例外）

```css
/* 玉质斜面：卡片的 1px 顶部内高光 + 外圈极淡内描边 */
--et-bevel: inset 0 1px 0 rgba(255,255,255,.72), inset 0 0 0 1px rgba(255,255,255,.26);
/* 深色：inset 0 1px 0 rgba(255,255,255,.06) */
/* 页面背景的极淡玉晕：仅限独立页首屏，<2% 不透明度，且不得出现在卡片内 */
```

除此之外不允许：`backdrop-filter`、`linear-gradient` 装饰、彩色光晕、
`box-shadow` 的无偏移纯色外圈。

## 3. 圆角与同心规则（本体系的核心）

### 3.1 阶梯

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--et-radius-xs` | 8px | 卡内 chip、徽标、小标签 |
| `--et-radius-sm` | 12px | 输入框、小按钮、分段项 |
| `--et-radius-md` | 16px | 按钮、行卡、内嵌卡 |
| `--et-radius-lg` | 22px | 一级卡片、列表容器 |
| `--et-radius-xl` | 28px | 设置弹窗、抽屉、浮层 |
| `--et-radius-2xl` | 36px | 主面板壳、独立页容器 |
| `--et-radius-pill` | 9999px | 胶囊、头像、状态点 |

### 3.2 同心弧（强制）

> **子元素圆角 = 父容器圆角 − 父子之间的内边距**，向下取最近的阶梯值。

例：22px 的卡片，内边距 16px，里面的按钮应取 `22 − 16 = 6 → 8px`（xs）；
内边距 8px 的内凹槽取 `22 − 8 = 14 → 12px`（sm）。

违反这条会出现"弧不共心"的视觉噪音——这是本体系最容易做错、也最容易被一眼看出的细节。
PR 自查时必须逐层核对。

### 3.3 禁止

- 全站同一个圆角（"全都圆"等于没有层级）。
- 圆角与直角混排（除了表格行分隔线与 3px 竖条）。
- 卡片左侧彩色竖条 + 圆角（AI 后台典型形态）。竖条只允许出现在**无圆角的**
  行内提示或时间线块上，且宽度 3px。

## 4. 材质与阴影

四级柔影，暖调（`rgba(38,42,36,·)`，不用纯黑）。阴影承担**层级**，不承担装饰。

| 令牌 | 用途 |
| --- | --- |
| `--et-shadow-r1` | 行卡、chip（几乎只有贴地感） |
| `--et-shadow-r2` | 一级卡片 |
| `--et-shadow-r3` | 浮动菜单、抽屉、粘底栏 |
| `--et-shadow-r4` | 弹窗、模态 |

规则：

- 同一视口内只出现**两级**阴影。三级同屏 = 层级失效。
- 卡片默认 `border-soft` + `shadow-r1`；悬停升到 `r2` 并 `translateY(-2px)`。
- 深色主题阴影加深但**降低不透明度**，靠 `--et-bevel` 与边框提亮。
- 卡片内不再套卡片。需要分组时用 `surface-2` 凹槽 + 无阴影，或加一条 8px 间距。

## 5. 排版

### 5.1 字体

| 角色 | 字体栈 |
| --- | --- |
| 标题（`--et-font-display`） | `"Songti SC", "Noto Serif CJK SC", "Source Han Serif SC", "STSong", Georgia, serif` |
| 正文（`--et-font-body`） | `"PingFang SC", "HarmonyOS Sans SC", "Noto Sans CJK SC", "Microsoft YaHei", -apple-system, sans-serif` |
| 等宽（`--et-font-mono`） | `"SF Mono", "JetBrains Mono", Menlo, Consolas, monospace` |

**标题用宋、正文用黑**：宋体的横细竖粗给标题"玉的骨"，黑体给正文"玉的润"。
这是本体系唯一的排版风险，也是识别度来源。宋体只用于页面标题、分区大标题与
强调数字，**不用于按钮、标签、表格**。

Windows 无优质宋体时回落到 Georgia/系统衬线；不接受 SimSun 在大字号下的渲染，
因此 `--et-font-display` 的 Windows 分支把 Georgia 放在 SimSun 之前。

### 5.2 字阶

| 令牌 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `--et-text-micro` | 11 / 1.4 | 徽标、角标 |
| `--et-text-meta` | 12 / 1.5 | 元数据、表格头 |
| `--et-text-caption` | 13 / 1.6 | 次要说明、表格正文 |
| `--et-text-body` | 15 / 1.7 | 正文（中文 15px/1.7 是舒适区） |
| `--et-text-lead` | 17 / 1.6 | 引导句、卡片主值 |
| `--et-text-h3` | 22 / 1.35 | 分区标题 |
| `--et-text-h2` | 28 / 1.25 | 页面分区大标题 |
| `--et-text-h1` | 40 / 1.15 | 页面标题 |
| `--et-text-hero` | 64 / 1.05 | 独立页主标题、空态大字 |

字重只有三档：**400 正文 / 500 强调 / 600 标题**。不再全站 500。

字距：中文标题 `0`；小号全大写英文标签 `+0.08em`；数字列 `tabular-nums`。

### 5.3 文字预算（"少大段文字"的硬约束）

> 一个卡片内：**标题 ≤ 12 字 + 说明 ≤ 40 字 + 至多 2 个操作**。

超出即必须转译（见 §6）或拆分。禁止把段落直接塞进卡片；段落只允许出现在
"关于/说明"类可折叠区。

## 6. 信息转译四式（把文字变成形状）

这是 v4 相对 v3 最大的能力增量。每条都是可执行的判断规则，不是风格建议。

### 式一：一句话 → 卡片

**触发**：连续说明性文字 > 2 行，或"标题：内容"形态的段落。
**做法**：拆成 `标题(≤12字) + 一行说明(≤40字) + 操作(0–2)` 的卡片，卡片进网格。
**反例**：把 3 条要点写成 `<ul>` 塞进一张大卡。

### 式二：过程 → 珠链

**触发**：有序的执行步骤、轮次、审批点、工具调用序列。
**做法**：竖向或横向的"珠链"——一条 2px 线（`border-soft`），每步一颗直径
10–14px 的圆珠，珠心用状态色，珠旁只放 `名称 + 一个数字`；详情进 hover 浮层或
展开区。已完成珠用 `--et-jade`，进行中用 `--et-accent` 并带 1.6s 呼吸，
失败珠用 `--et-danger` 并加 1.5px 外环。

文字量从"N 行日志"降到"珠 + 名称"，同一屏能放 3 倍的信息。

### 式三：比例 → 玉环

**触发**：百分比、预算占用、配额、完成度。
**做法**：直径 44–72px 的圆环，`stroke-linecap: round`，12–20% 的轨道，
进度弧用 accent（或按语义着色），环心放数值。**不使用横向进度条**做主要表达
（横条只用于表格行内的极小空间）。

### 式四：趋势 / 序列 → 条带

**触发**：时间序列、token 用量、耗时分布。
**做法**：高度 28–40px 的 sparkline 条带，无坐标轴、无网格，只标 1 个高亮点
（最大或最新）与首尾值。多序列最多 3 条（accent / jade / sand）。

### 式五：状态 → 玉质色阶 + 形

状态三元组，任一状态必须同时满足"色 + 形 + 字"三者中的两者：

| 状态 | 色 | 形 | 字 |
| --- | --- | --- | --- |
| 待命 | `border` | 空心细环 | 「待命」 |
| 进行中 | accent | 实心珠 + 呼吸 | 「进行中」 |
| 等人/卡点 | warn | 实心珠 + 3px 外环 | 「等人」 |
| 失败 | danger | 实心珠 + 斜切 | 「失败」 |
| 完成 | jade | 实心珠 + 内勾 | 「完成」 |

### 6.1 动效预算

- 每个视图**一次**编排式入场：卡片按 40ms 递增错峰，`translateY(8px)+scale(.985)
  → 原位`，380ms，`cubic-bezier(.22,.61,.24,1)`。
- 交互微动效：按压 `scale(.985)` 120ms；悬停升起 2px / 阴影升一级 220ms。
- **常驻循环动画每屏 ≤ 2 处**，只允许"进行中"的呼吸与活线流动。
- 全部动效只碰 `transform / opacity / filter / color / box-shadow`。
- `prefers-reduced-motion: reduce` 下移除位移与循环，只保留 120ms 透明度变化。

## 7. 组件规则

### 按钮

| 类型 | 规格 |
| --- | --- |
| 主 | `--et-accent-fill` 底、`--et-accent-on` 字、`md` 圆角、高 40、内距 10×20、`shadow-r1` |
| 次 | 透明底、1px `--et-border`、`--et-fg` 字；悬停 `surface-2` |
| 幽灵 | 无边框，`--et-muted` 字；悬停 `surface-2` |
| 破坏 | 透明底、danger 描边（danger 30%）、danger 字；**两击确认** |
| 胶囊 chip | `pill`、高 28、内距 6×12、11–12px |

按钮高度 40（触控 ≥36），不使用纯黑按钮，不使用渐变按钮。

### 输入

`surface-3` 底（不是纯白）、1px `--et-border`、`sm` 圆角、高 40、内距 10×14。
聚焦：边框转 `--et-accent` + `0 0 0 3px accent 22%` 光环，同时**轻微内阴影收拢**。
错误：danger 边框 + 就地说明，不用全局红框。

### 卡片

| 层级 | 规格 |
| --- | --- |
| 一级卡 | `surface` + `border-soft` + `shadow-r1` + `lg` 圆角 + 内距 20 |
| 强调卡 | 同上 + `--et-bevel` + `shadow-r2`（每屏 ≤ 1 张） |
| 凹槽 | `surface-2`、无边框无阴影、`md` 圆角、内距 12 |
| 行卡 | 高 ≥ 56、`md` 圆角、内距 14×16、悬停升 `r1→r2` |

### 表格

只在真正的多维数据处使用。表头 12px `--et-muted`、行高 ≥ 48、仅横向
`border-soft` 分隔、数字右对齐 tabular。**表格行不得有圆角**（与卡片区分）。

### 弹窗

`xl` 圆角、`shadow-r4`、遮罩 `rgba(22,25,23,.42)` + `blur(2px)`（唯一允许的
blur，仅遮罩）、内距 24。设置弹窗维持 880×720 与 200px 导航。

### 浮层菜单

`lg` 圆角、`shadow-r3`、内距 6（菜单项 `sm` 圆角）、条目高 36、分隔用 1px
`border-soft` 且左右内缩 12px。

### 图标

沿用 `@eterna/ui/icons`，24 网格、**1.6px** 描边（v3 是 1.75，v4 更细以配合
细弧）、圆头圆角、`currentColor`。图标容器：裸图标（无背景）或 32px `sm` 圆角
的 `surface-2` 底；**禁止圆形彩色底图标阵列**。

## 7a. 叠层与提示（位置即语义）

浮出物不是"盖在页面上的东西"，而是**产品在争用用户的注意力**。因此位置不是审美
选择，是产品契约：同一时刻，用户只能被一件事打断。

### 7a.1 三个表面，三个固定席位

| 表面 | 席位 | 语义 | 生命周期 | 抢焦点 |
| --- | --- | --- | --- | --- |
| **决策层**（工具审批 / 用户提问） | 贴输入卡顶边向上浮出 | 这条对话需要你决定 | 直到用户处理；超时按拒绝 | 是 |
| **Toast**（消息提示） | 顶部中央 | 某个一次性动作的结果 | 4 秒自散（可带 1 个动作） | 否 |
| **通知中心**（消息与审批） | 设置弹窗分区 | 需要留档的事件 | 永续，直到标记已读 | 否 |

**铁律：三者不得共用同一块屏幕区域。** 现状是审批卡与提问卡都挂 `body`、都与
`fixed top:16px`、都是 `z-index:10000`——两张卡同时挂起必然重叠；而且宿主原生
toast 在 `top:40px / z-index:1100` 居中，会被这两张卡直接压住。这不是样式问题，
是布局契约缺失。

### 7a.2 决策层：贴输入卡，不进顶部

宿主在输入卡顶边留了零高度锚点（`.overlayAnchor{height:0;position:absolute;inset:0 0 auto}`，
`conversation.input.overlay` 席位），这就是决策卡的正确落点：

```css
/* 决策层容器：锚在输入卡顶边，向上生长 */
.et-decision-layer {
  position: absolute;
  inset-inline: 0;
  bottom: calc(100% - 6px);      /* 与输入卡顶边重叠 6px：视觉上"长"在上面 */
  display: flex; flex-direction: column; align-items: center;
  gap: var(--et-space-2);
  z-index: 200;                   /* 低于宿主 toast(1100)，避免抢弹出层 */
  pointer-events: none;           /* 容器不吃点击，只有卡片吃 */
}
.et-decision-card {
  pointer-events: auto;
  width: min(760px, 100%);
  border: 1px solid var(--et-border-soft);
  border-radius: var(--et-radius-lg);   /* 父 22 − 内距 0，同心规则取 lg */
  background: var(--et-surface);
  box-shadow: var(--et-shadow-r3);
  overflow: hidden;
}
```

规则：

1. **不进顶部、不用遮罩、不加 blur**。决策卡不阻断阅读——用户可以滚回去看上下文。
2. 卡片是**会话作用域**的：审批项自带 `sessionId`，只出现在它所属的会话里。
3. **遮住信息流时必须补偿**：把决策层实测高度写进信息流的下内距（`ResizeObserver`
   → `padding-bottom`），并滚到底。否则卡片压住的正是不该被挡的证据。
4. 队列顺序 = 到达顺序；**宽屏纵向排队最多 2 张**，超过则折叠为"另有 N 项"。
5. 语义色只用边框/图标，不用整片底色：审批 = `--et-warn`，提问 = `--et-accent`。
6. 倒计时是**贴卡片顶边的 2px 条**，不是独立一行——否则卡内出现一条横线把内容切断。

### 7a.3 Toast：顶部中央，且只有一个队列

宿主已有 `@deepseek-ai/dsh-client-ui-primitives` 的 `Toast` 原子（`role="alert"`、
`top:40px`、居中、`z-index:1100`、`max-width:min(640px,100vw-48px)`）。**不新建
toast 系统**，走宿主原子或 `workspace.toast.content` 工厂席位。

| 项 | 规则 |
| --- | --- |
| 位置 | `inset-block-start: 40px`（宿主既有值，不改）；水平居中 |
| 宽度 | `min(520px, 100% - 32px)`，单行优先，超长两行截断 |
| 同时条数 | ≤ 2，超出排队；同 id 覆盖而非堆叠 |
| 停留 | 4 秒；带动作的 6 秒；出错不自动消失 |
| 动作 | 至多 1 个（撤销 / 重试 / 压缩），文字按钮，不做图标按钮 |
| 语气 | 成功=反色胶囊 + jade 勾；警告=sand；失败=danger 底 + 白字（唯一允许的实心语义底） |
| 禁止 | 禁止从底部长出、禁止出现在输入框内、禁止与决策层同区 |

### 7a.4 通知中心：toast 的留档面

toast 是瞬时的，通知中心是永续的，**两者共用同一事件源**（一次事件同时写入
`notifications` 表 + 触发 toast）。分区落在设置弹窗（`settings.section`，
现有 `NotificationsSection`「消息与审批」即此席位）。

- 未读数 = **待处理项**数量，不是"看过未看过"——清零发生在真正处理之后。
- 单条 = 左侧 6px 未读点 + 一行事件 + 一行来源与相对时间；不接受多行正文。
- 顶部右对齐一个「全部标为已读」；不做逐条删除（删除是审计面的事）。

### 7a.5 层级表（全产品唯一真值）

| z | 用途 | 备注 |
| --- | --- | --- |
| 1–40 | 页面内粘性头、局部浮层（下拉、菜单） | 见 §7 浮层菜单 |
| 100 | 锚定弹层（模型菜单、上下文菜单） | `model-menu.tsx` 现用 1300，属越级，迁移时下调 |
| **200** | **决策层（贴输入卡）** | 本节新增 |
| **1500** | **Toast（产品自建时）** | 走宿主原子时用宿主的 1100 |
| 1000 | 设置弹窗 / 模态遮罩 | 必须高于决策层，低于 toast |
| 1100 | 宿主原生 toast | **不得抢占** |
| 2147483000 | 账户菜单等极端逃生舱 | 仅历史遗留，新代码禁止 |

### 7a.6 响应式：位置固定，形态收缩

位置规则在任何宽度下都不变（决策贴输入、toast 占顶部、通知进设置），变的只是形态：

| 断点 | 决策层 | Toast |
| --- | --- | --- |
| ≥1100 | 纵向排队 ≤2 张，宽 `min(760, 100%)` | `min(520, 100%-32)` |
| 760–1100 | 同上，单卡宽 `min(680, 100%)` | 同上 |
| <760 | **一次只呈 1 张**，其余排队并用「另有 1 项待授权/拍板」切换条轮转；卡宽贴满（内距 16） | 宽 `100% - 24`，字号降到 11 |

窄屏为什么不并排两张：390×844 下两张卡合计 440px（占视口 52%），信息流被压成
一条缝。一次一张 + 可轮转，既保住"能看到上下文"，又保证不丢待办。

### 8c. 增量扫描：远程 main 新面前的覆盖缺口（2026-11-19 补）

远程 main 在本轮工作期间前进 60 个提交，新增一个**此前完全未被 v4 覆盖的前端面**：
`packages/knowledge-admin`（992 行客户端，七标签面板：文档 / 编辑 / 问答 / 提案 /
导入 / 成员 / 审计，注册 `main` + `sidebar.panellist` 两席位）。

扫描结论（实测，非推断）：

| 项 | 实测值 | 与规范的关系 |
| --- | --- | --- |
| 字面色值 | 14 个 hex + 9 个 rgba | **违反**铁律 1（只能用 `--et-*`） |
| `--dsw-alias-*` 令牌名 | **9 个全部不存在于上游** | **严重**：兜底色生效 |
| 字面圆角 | 6 / 8 / 10 / 999px | **违反**阶梯（6、10 不在阶梯内） |
| 字面字号 | 11 / 12 / 13 / 14 / 20px | 部分违规（14 不在 v4 字阶） |
| 断点 | `max-width:900px` | **违反**（只允许 1100/760/640） |
| 图标描边 | 1.75 | 规范要求 1.6 |
| `font-weight:500` | 0 | 合规 |

**9 个上游不存在令牌名的实证**：对上游 `dsh-web-frontend` 的 CSS 逐一 grep，
`--dsw-alias-fg-primary` / `fg-secondary` / `fg-danger` / `accent` / `bg-base` /
`bg-elevated` / `bg-hover` / `bg-subtle` / `border-subtle` **定义次数均为 0**。
该插件注释自称「只用宿主主题令牌 `--dsw-alias-*`（深浅主题随壳；不写死颜色）」，
实际每个令牌都带字面兜底（`#1b1b1b` / `#2563eb` / `#fff` / `#c62828`），
**因此界面长期跑在电光蓝 `#2563eb` 兜底上，深浅主题都不跟随**。

> 这是「注释不可作为合规证据」的实例：合规必须由 lint 机器验证。

**根因不在插件作者，在护栏本身（两道断点）**：

1. `SCAN_DIRS` 是**手写白名单**（11 个目录）——新包默认不进扫描面；
2. `walk()` 只收 `.ts/.tsx/.html`——**纯 `.js` 客户端半边即便进了扫描面也被整体跳过**
   （`knowledge-admin/src/client/index.js` 正是手写 `h()` 的 `.js`）。

两道都已修：全覆盖（16 个目录 / 249 个文件）+ 文件过滤补 `.js/.jsx/.mjs`。
**实测验证**：把该包真拷进工作区后 lint 报出 **23 项**（8 个上游不存在令牌名、
11 处字面色值、3 档越阶圆角、1 个 900px 断点），全部命中且无误伤其他包；
移出后恢复通过。

> 只改第一道断点时 lint 依旧全绿——扫描目录从 11 变 16 看着更好，新包却仍被跳过。
> **这种"看起来修好了"的假绿只有真拷进去跑才暴露。** 这正是本仓库「单包绿 ≠ 全仓绿」
> 教训的又一次复现。

**原型已覆盖该面**：可交互原型第 8 视图「知识库管理」（七标签可切、编辑面脏检查生效、
三视口 0 溢出）；无限画布第 11 页（文档列表 + 数据源 + 提案三栏对照）。

## 9. 可访问性（不放松）

- 正文与背景 ≥ 4.5:1；大字号与 UI 元件 ≥ 3:1；深色主题逐条复测。
- 焦点可见：`0 0 0 3px accent/22%` + 边框转 accent，不允许 `outline:none` 无替代。
- 触控目标 ≥ 36px（推荐 40）。
- 语义标题不跳级；图标按钮必须有 `aria-label`。
- `prefers-reduced-motion` 全覆盖。
- 状态除颜色外必须有形状或文字（见 §6 式五）。
- 宋体标题不影响可读性：标题最大行宽 ≤ 20 字/行。
