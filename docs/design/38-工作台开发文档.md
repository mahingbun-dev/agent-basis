## 3. 范围与不做什么

**做**（32 号 §2 WS-D 行「原型四件（先行）→ Canvas 图 + 五视图接 mock SSE → 实接 DomainEvents」）：

- 新建 `packages/workbench`（Tier2）：Host 半边（SSE 流 + 数据投影）+ Browser 半边（keyed main panel 五视图一检查器 + workspace slots 深视图 + 会话侧任务侧栏 / Attention 横幅）；
- SSE 传输层（mock 事件源先行，可与 WS-A 并行——30 号 §6「SSE 传输层｜管理面 API 扩展｜可与 P1 并行开发（先以 mock 事件流驱动前端）」）；
- M4 实接：五视图数据源从 mock 切换 Engine DomainEvents（33 号 G2-D11）。

**不做**（逐条有出处）：

- **不建独立页面**（30 号 §4-1；AGENTS.md 铁律 1；26 号 §2.1-3）；
- **不做全局时间轴回放**（30 号 §7-2「全局时间轴回放不做」；负向断言见 33 号 G2-D3）；
- **不移植 superagent 面板/HTTP 层**（34 号 §2.6：`SA/src/client/`、`views/`、`cards.ts`、`http.ts` 不移植，面板由 30 号 workbench 承接；24 号 §8.2）；
- **不改 tasks 内核**（workbench 只读消费 DomainEvents 与 EngineForPeople 面——34 号 §3 EngineForPeople 即「面板/workbench 与审批卡动作持有」的角色接口）；
- **渠道卡片形态的渲染不做在 workbench**（归 channels `cards.ts`——26 号 §2 channels 行「`cards.ts` 增加报告六态渲染」；原型 `attention-card` 两形态齐全，workbench 只实现站内横幅形态，见 T7）；
- **超范围的行为一律不做**：30 号未定义的行为进 §10 开放问题，不自行补设计。

## 10. 开放问题（设计缺口，如实记录；不得自行补设计）

1. **O-1｜11 个 DomainEvents 的具体枚举**：30 号 §2 视图 2 称「Engine 的 11 个 DomainEvents（superagent 已枚举，移植保留）」，但本仓设计文档（30/34 号）均未列出 11 个事件名；superagent 源码副本不在本仓（B8 同源核查）。实接（T15）与 mock 事件命名（T5）需以 WS-A 落地的 `packages/tasks/src/core/ports.ts` DomainEvents 端口清单为准——**建议 WS-A 定稿时回填事件清单，mock 阶段不得虚构事件名**。
2. **O-2｜mock 事件载荷 schema 是否预先冻结**：30 号 §3/§6 只定「先以 mock 事件流驱动前端」，未定 mock 载荷与 DomainEvents 的对齐纪律。若不冻结，M4 实接可能重写投影层；若冻结，则 mock 阶段就要预定事件 schema（依赖 O-1）。需拍板。
