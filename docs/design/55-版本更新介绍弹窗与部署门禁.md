## 0. 一页速览

| 维度 | 结论 |
| --- | --- |
| 形态 | 全局遮罩弹窗，880×720（与设置弹窗同尺寸族），横向 scroll-snap 幻灯片，图左文右 |
| 触发 | 登录后客户端就绪，`GET /access/api/release-notes` 返回「本版未读」才弹；不阻塞首屏 |

| 关闭语义 | X / Esc / 点遮罩 / 「以后再看」/「知道了」**一律记已读**；重看去「设置 → 更新记录」 |
| 内容源 | 仓库内 `releases/<version>/release.json` + `assets/`（图文与视频），随镜像走 |
| 版本源 | 仓库根新增 `VERSION`，为唯一事实源；镜像 tag 必须与之相等 |
| 门禁 | `scripts/release-notes-gate.mjs` 12 条（G-RN-01..12），接入**部署前**、CI、`verify.sh`；entrypoint fail-closed |
| 不做 | 不做独立页面入口、不做用户级永久退订、不弹内部预发布（rc）内容 |
| 归属 | 全部落 `@eterna/access`（路由面独占），不新开插件包 |

为什么放进 access 而不是新插件：AGENTS.md 规定路由面独占 eterna-access、设置类功能 = `settings.section` 分区。本功能的三个面（HTTP 端点、设置分区、body 级遮罩）恰好都是 access 已有的能力，新增独立包只会多一套租户/守卫要维护。

## 1. 目标与不做什么

**要拿到的东西**

1. 用户**知道**这一版变了什么——不是 changelog 链接，是看得懂的图 + 三句话。
2. 用户**不被重复打扰**——同版本只弹一次，任何关闭动作都算看过。
3. 用户**想回看能回看**——「设置 → 更新记录」永久保留，按版本倒序。
4. 运营**写不出空白**——没有合规的更新包，部署直接失败。

**不做**

- 不做 `/whats-new` 独立页（违反前端铁律 1）。
- 不做「不再提示」永久退订（等于让功能失效；退订诉求由「以后再看 + 设置里回看」承接）。
- 不做自动轮播（自动翻页会被认为抢注意力，且打断读屏）。
- 不做未登录可见（登录页不在应用壳内）。
- 不做 rc / 内部预发布的面向终端用户的公告（`announce:false`）。

## 2. 产品形态与交互

### 2.1 结构（6 页为典型形态）

```
┌──────────────────────────────────────────────────────────────┐
│ v0.2.1 │ 2026-11-24 发布                              [×]    │ 头 56px
├──────────────────────────────────────────────────────────────┤
│                                                              │
│   ① 封面      版本号 + 一句话主题 + 3 枚亮点 chip + 恒环图形   │
│   ②..⑤ 图文   图左 62% / 文右 38%（kicker·标题·正文·要点）      │
│   ⑥ 收尾      勾选标记 + 两张去路卡（更新记录 / 使用指南）       │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ ▬▬▬▭▭▭▭  3 / 6            以后再看   上一页   [下一页 ›]      │ 脚 64px
└──────────────────────────────────────────────────────────────┘
```

- 横向滚动容器 + `scroll-snap-type: x mandatory`：触控板/移动端可直接滑，桌面用按钮与方向键。
- 进度用**分段条**而不是圆点：段数 = 页数，同时表达「还有几页」，并可直接点选跳转。
- 最后一页主按钮文案变「知道了」，隐藏「以后再看」（已到终点，无需再分叉）。

### 2.2 交互与状态矩阵

| 动作 | 结果 | 记已读 | 备注 |
| --- | --- | --- | --- |
| 关闭 × / Esc | 关闭弹窗，焦点回原位 | 是（`close`） | 焦点必须回到打开前元素 |
| 点遮罩空白 | 关闭 | 是（`backdrop`） | 弹窗内部点击不穿透 |
| 「以后再看」 | 关闭 + 角落轻提示「可在 设置 → 更新记录 重新查看」 | 是（`skip`） | 提示 4s 后自动消失，不进通知中心 |
| 走到末页「知道了」 | 关闭 | 是（`done`） | |
| 设置 → 更新记录 → 选某一版 | 打开该版弹窗 | 仅当该版未读 | 回看不改已读时间 |
| 下一版发布 | 再次弹出 | 新版本新行 | 旧行保留，构成历史 |

**已读口径**：同账号同版本一次即永久。换设备、换浏览器、清缓存都不再弹——这是服务端行的意义。多实例（base / super）各有独立数据根，因此各自独立记已读，符合现有部署拓扑。

**不补课**：连跨两个版本没用产品的用户，只看到最新一版，不按顺序补弹旧版本。发布说明的职责是「现在能做什么」，不是档案；历史在「更新记录」里查。

### 2.3 与其它浮层的关系

| 浮层 | 优先级 | 规则 |
| --- | --- | --- |
| 工具审批卡（`eap-*`） | 最高 | 审批卡是 body 级历史实现，不与之做 z-index 竞争；**有待决审批时不展示更新**，30s 后重试 |
| 提问卡（`ask_user_question`） | 高 | 同上 |
| 更新弹窗 | 中 | 占 `shell.overlay` 一个席位；一次只挂一个实例，不弹时渲染 null |
| 设置弹窗 | 低 | 更新弹窗打开时若用户点设置，先关更新并记已读（不叠层） |

### 2.4 可访问性

- `role="dialog" aria-modal="true"`，`aria-labelledby` 指向当前页标题，焦点陷阱（Tab 循环），Esc 关闭。
- 翻页时 `aria-live="polite"` 播报「第 3 页，共 6 页：不再有假运行中」。
- 图版 `role="img"` + 完整 `aria-label`；文字要点不以图片承载（图片裂了仍能读全文）。
- `prefers-reduced-motion`：取消滑入动画，翻页用 `behavior:auto`；视频只出首帧海报。
- 触控目标 ≥ 40px；`focus-visible` 统一 3px 光环。
- 响应式：≥861 图文两栏；760 以下堆叠（图上文下，页内可纵向滚动）；640 以下全屏无圆角。

### 3.2 文案与素材规范（门禁可判，人能写）

| 项 | 规则 | 理由 |
| --- | --- | --- |
| 页数 | 3–8 页（含封面与收尾） | 少于 3 页不像一次发布；多于 8 页没人看完 |
| 标题 | ≤ 18 个汉字 | 一屏一卖点，超了就说明该拆页 |
| 正文 | ≤ 120 个汉字 | 读者在弹窗里只读三行 |
| 要点 | ≤ 4 条，每条 ≤ 24 字 | 再长就是正文 |
| 图注 | ≤ 40 字 | 图注是补充，不是第二次正文 |
| 封面亮点 | 恰好 3 枚 | 三件事记忆点上限 |
| 截图 | 1440×900（16:10）、webp、≤ 600KB | 与图版显示宽度 560px@2x 匹配 |
| 动图 | webm（VP9）≤ 8s、≤ 2MB，且必须配 poster | 只作为「动作」补充，缺 poster 直接拒 |
| 单版资产 | ≤ 6MB | 首次打开不该等图 |
| 禁用词 | 内部代号（`dsh-`、`PR #`、`session-`）、emoji、`TODO`、未实测数字 | 面向用户，不是开发者日志 |
| 主题 | 截图统一浅色主题 | 深浅混排会花；弹窗自身跟随用户主题 |

### 3.3 素材生产（脚本自动截图 + 文案手写）

**D5 已定：截图走脚本，不手抠。** 入口 `node scripts/release-shots.mjs <version>`：

1. 用**本机 dsh 与本地 profile** 真启动一份隔离实例（`ETERNA_PROFILE_HOME` 临时目录 + 播种管理员凭据 + OS 分配端口），不碰生产数据根。
2. `playwright-core` + 系统 Chrome（`CHANNEL=chrome`，可 `CHROME_PATH` 覆盖）在 1440×900、`deviceScaleFactor=1`、浅色主题下按 `shots.plan.json` 逐个界面取证；每张图先落 PNG。
3. **零新增依赖的 webp 输出**：playwright-core 1.65 起 `page.screenshot({ type: 'webp', quality })` 内建 libwebp（实测 `coreBundle.js` 走 encodeWebp wasm），直接出 1440×900 webp——不需要 `sharp`/`cwebp`/`ffmpeg` 二进制。
4. 写 `releases/<v>/assets/*.webp` + `.shots.json`（浏览器版本、视口、逐文件 sha256、captureAt），并回填 `release.json` 的 `media.sha256`。
5. 需要「动作」的页用 `record-browser-gif` 技能录 webm，`ffmpeg -c:v libvpx-vp9 -crf 36` 压缩，poster 取首帧。

验收补充（2026-11-24 实跑）：`--viewport=760x900`、`--color-scheme=dark` 两个
开关与 `--plan/--out` 组合，用于对**弹窗本身**按断点与深浅主题取证；正式素材
仍是固定 1440×900 浅色。`RELEASE_SHOTS_DSH=<内核 bin.js>` 允许换运行时——本机
pnpm 树缺 peer 时（`autoInstallPeers:false` 的已知坑）用一份 npm 扁平安装即可，
不要动仓库 node_modules。

> 本次截图顺带修掉一处部署漂移：`/clear` 行只落在 `profiles/eterna-*`（verify
> 脚本用的开发档），容器真正渲染的 `docker/profile/*.template` 两处漏行，生产
> 形态里命令不存在。两模板×两处已补齐（与 profile 同文），`release-shots` 的
> super 形态实跑确认菜单里出现 `clear`。

CI 侧（`.github/workflows/ci.yml` 新 job `release-shots`）：`workflow_dispatch` 手动触发，与本地同一条命令在 runner 上重跑一遍并把产物作为 artifact 上传（runner 自带 Google Chrome，`playwright-core` 随 `packages/browser-relay` 已装）。**它不比对像素**——跨机器字体渲染天然有差异，比对会变成噪声；它证明的是「流水线在任何一种机器上都还能跑通」。合规性由 `release-notes-gate` 的尺寸/大小/哈希断言负责，`--check` 模式只断言 `assets/` 与 `.shots.json` 同步、清单引用完整。

> 手绘示意图（本轮原型里的 4 张 SVG）不进入发布资产：门禁只收 webp/png/jpg，且 `alt`/`caption` 若写「示意图」必须在 `notes` 字段声明原因（如无 GUI 的纯配置修复）。

### 4.1 归属与文件

| 文件 | 角色 |
| --- | --- |
| `packages/access/src/release-notes.ts` | Host 半边：清单加载/校验、已读读写、资产流式响应 |
| `packages/access/src/routes.ts` | 追加 3 条路由（现有 if 分发风格） |
| `packages/access/src/store.ts` | 新表 `release_notes_seen` + 迁移 + 两处用户级联删除 |
| `packages/access/src/client/release-notes.tsx` | Client 半边：遮罩弹窗、设置分区「更新记录」 |
| `packages/access/src/client/styles.ts` | 追加 `--et-*` 样式块（不新增字面色值） |
| `packages/access/src/client/index.tsx` | 注册 `settings.section`；登录后挂 `installReleaseNotes()` |
| `packages/access/tests/release-notes.spec.ts` | 清单校验 + 已读矩阵 + 资产守卫 |
| `releases/<version>/` | 清单与资产（随镜像） |

### 4.2 服务端

**路由**（全部在既有会话守卫之后；未登录 401）

| 方法与路径 | 响应 |
| --- | --- |
| `GET /access/api/release-notes` | `{ current: {version,releasedAt,theme,summary,highlights,slides}, seen: boolean, history: [{version,releasedAt,theme,seen}] }`，`Cache-Control: no-store` |
| `POST /access/api/release-notes/seen` | body `{version, via}`；`via ∈ done\|skip\|close\|esc\|backdrop`；幂等 upsert；204 |
| `GET /access/api/release-notes/asset/<version>/<file>` | 资产字节流；`Content-Type` 按扩展名白名单；`Cache-Control: public, max-age=31536000, immutable`（路径含版本，天然不可变） |

**资产守卫**（不信任清单以外的一切）

- 文件名必须精确命中该版本 `assets/` 目录列表；拒绝 `/`、`..`、非白名单扩展。
- 只读、限 8MB、`nosniff`；不提供目录列表。
- 版本号形如 `^\d+\.\d+\.\d+(-[a-z0-9.]+)?$`，防止路径注入。

**清单加载**：启动时读 `releases/` 目录，取 `VERSION` 指向的版本；解析失败 → 记审计 + 关闭功能（不拦启动，弹窗属装饰性能力，不能让它把产品弄挂）。部署门禁已保证不会走到这条路。

**新表**

```sql
CREATE TABLE IF NOT EXISTS release_notes_seen (
  user_id  INTEGER NOT NULL REFERENCES users(id),
  version  TEXT    NOT NULL,
  via      TEXT    NOT NULL,
  seen_at  TEXT    NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (user_id, version)
);
```

迁移用既有幂等风格（构造器内 `CREATE TABLE IF NOT EXISTS`）；`store.ts:408-413` 与 `:758-759` 两处删除用户时必须同步清表，否则删用户会撞 FK（2026-11-10 已踩过一次）。

### 4.3 客户端

**挂载：注册进 `shell.overlay`（原生扩展点，不用 body 级 createRoot）**

`shell.overlay` 是 layout 声明的 `list/root` 槽，语义正是「框级浮层、在一切列之上、不属于任何功能」；
上游已有 17 个占用者，其中两个就是真正的对话框（`workspace.session-rename`、`workspace.session-archive`）。
新 `id` 是增量、不遮蔽任何上游 UI——这正是 AGENTS.md 要求的原生扩展点，而 `approval-card` 那种
`createRoot(document.body)` 属于历史实现（该卡 2026-11-13 落地时未找到此槽），不适合作为新功能的先例。

```ts
ctx.slots.inject(shell.overlay, () => ctx.slots.register({
  name: shell.overlay,
  id: eterna-access.release-notes,
  order: 80,
  locale: NS,
  inject: () => ({ t }),
}, ReleaseNotesOverlay))
```

组件内部状态机（槽只负责「有席位」，弹不弹由数据决定，不弹就 `return null`）：

```
mount
 ├ /access/api/me 未登录 → return null（登录页不在应用壳内）
 ├ requestIdleCallback(≤1.5s) → GET /access/api/release-notes
 ├ seen===true → return null
 ├ 有待决审批 → 30s 后重试（最多 20 次），期间 return null
 └ seen===false → 渲染遮罩；关闭时 POST seen → return null
```

- **必须给根节点 `pointer-events: auto`**：`shell.overlay` 层本身可穿透，占用者自己决定是否接管指针。
- 不占首屏关键路径：等 `/me` 之后、等 idle，最坏 1.5s 后出现，不跳布局。
- 一次性：同一页面生命周期内只判定一次（组件内 ref），路由切换不重弹。
- 图片：首图 `eager`，其余 `loading="lazy"`；idle 时预取下一张。图片 404 → 就地降级为文字版（不显示破图，图注仍显示）。
- 视频：仅当 `!prefers-reduced-motion` 时挂 `<video autoplay muted loop playsinline poster>`，且在 slide 进入视口后才 `play()`，离开即 `pause()`。

**设置分区「更新记录」**

- `settings.section`，`id: eterna-access.release-notes`，`order: 42`（账号 40 / 用户 41 / 更新记录 42）。
- 列表：版本号 + 日期 + 主题 + 未读点；点击用同一遮罩组件打开该版（`{ version }`），关闭记已读。
- 收尾页「完整更新记录」卡的动作 = 打开设置弹窗并切到本分区。优先走上游公开面（access 已有先例：
  `ctx.slots.entries(sidebar.settings)[0].store.create().actions.openSection(...)`，
  `index.tsx:533-546`）；若 `openSection` 不认本分区 id，则退化为「在弹窗内切到历史列表」，不依赖外壳。
- 空态：`暂无更新记录`（首次部署即当前版，不会为空）。
- 全员可见；无写操作，不涉及 admin 门。

### 4.4 版本与清单的对齐

- 仓库根 `VERSION`（纯文本，如 `0.2.1\n`）是**唯一事实源**。
- `releases/<VERSION>/release.json` 必须存在且 `version === VERSION`。
- 镜像 tag 必须等于 `VERSION`（`ETERNA_IMAGE=eterna-agent:0.2.1`）；内部补丁用 `0.2.1-3` 这类后缀时，清单仍按 `0.2.1` 取——后缀允许，但内容变了必须升 `VERSION`。
- 容器内读取路径 `/repo/VERSION` 与 `/repo/releases/`（access 从 `/repo/packages/access/src` 相对解析，等价）。

## 5. 部署门禁（本需求的核心约束）

### 5.1 为什么必须新增 `VERSION`

现状（2026-11-24 实测）：产品版本只存在于未跟踪的 `.env`（`ETERNA_IMAGE=eterna-agent:0.2.0-rc.5-10`）与镜像 tag 里，容器内 `dsh --version` 只会报上游内核 `0.2.2-rc.5`，`/repo/package.json` 是 `0.0.0`，没有 `CHANGELOG`，CI 也不碰 docker。**没有版本号，就没有「本版更新内容」这个命题**。

因此第一步是把版本变成可判定的事实：`VERSION` 文件 + 镜像 tag 一致。这是门禁的前提，也是「更新记录」列表排序的依据。

### 5.2 门禁十二条（G-RN-01..12）

`node scripts/release-notes-gate.mjs [--version=<v>] [--hash] [--json]`

| 编号 | 断言 | 失败示例 |
| --- | --- | --- |
| G-RN-01 | `releases/<v>/release.json` 存在且为合法 JSON | 忘了建目录 |
| G-RN-02 | `release.json.version === VERSION` | 复制上一版忘改版本号 |
| G-RN-03 | `releasedAt` 为 ISO 日期且不超过今天 +1 天 | 写成 `2026/11/24` |
| G-RN-04 | `slides` 长度 3–8，首 `cover`、尾 `end`、至少 1 个 `feature` | 只有封面和收尾 |
| G-RN-05 | 每条 feature 的 `kicker/title/body` 非空且在 §3.2 字数内 | 正文 300 字 |
| G-RN-06 | `media.src` 命中 `assets/` 且扩展名 ∈ {webp,png,jpg} | 引用 `../secret.png` |
| G-RN-07 | 图片尺寸 ≥ 1200×750、比例 1.5–1.75、单张 ≤ 600KB | 传了 4MB 的 PNG |
| G-RN-08 | `media.sha256` 与文件实算一致（`--hash` 可回填） | 换图没更新哈希 |
| G-RN-09 | `media.alt` 非空；`caption` ≤ 40 字；`motion` 存在时必须同目录有 poster 且 ≤ 2MB | 动图没海报 |
| G-RN-10 | 单版资产合计 ≤ 6MB，且 `assets/` 内无未被引用的孤儿文件 | 传了两版图 |
| G-RN-11 | 禁用词扫描（`dsh-`、`PR #`、`session-`、`TODO`、emoji 码位） | 文案里写「见 PR #155」 |
| G-RN-12 | `announce:false` 仅允许带预发布后缀的版本；正式版必须 `true` | 正式版偷偷不公告 |

通过时输出 `PASS 12/12 · 0.2.1 · 4 features · 2.1MB`，并写 `releases/<v>/.gate.json`（含清单与资产整体 sha256），供 `verify.sh` 事后比对。

### 5.3 接入点（四道，前紧后松）

| 位置 | 时机 | 失败后果 |
| --- | --- | --- |
| ① `deploy/release-notes-check.sh`（新） | **部署前**，人按 SOP 跑；`deploy/README.md` 两处序列各插一行 | 不进 build，最便宜 |
| ② `.github/workflows/ci.yml` 新 job `release-notes-gate` | PR / push main | 合不进去 |
| ③ `docker/entrypoint.sh` | 容器启动，`/data` 预检之后、profile 渲染之前 | **拒启**（fail-closed） |
| ④ `deploy/verify.sh` 第 15 项 | 部署后 | 判定部署失败，走回滚 |

① 是唯一能"阻止"的层，③ 是唯一"自动化"的层——两者都要，因为有人会绕过 SOP 直接 `docker compose up -d`。

**entrypoint 形态**（③）

```sh
# 版本与发布说明：缺当前版本的说明 = 该镜像不合规，拒启（fail-closed）
VERSION="$(tr -d '[:space:]' < /repo/VERSION 2>/dev/null || true)"
if [ -z "$VERSION" ]; then
  echo "[entrypoint] FATAL 缺少 /repo/VERSION——镜像不合规" >&2; exit 1
fi
if [ ! -s "/repo/releases/$VERSION/release.json" ]; then
  if [ "${ALLOW_MISSING_RELEASE_NOTES:-0}" = "1" ]; then
    echo "[entrypoint] WARN $VERSION 缺发布说明，ALLOW_MISSING_RELEASE_NOTES=1 已放行（仅限热修）" >&2
  else
    echo "[entrypoint] FATAL 缺少 $VERSION 的发布说明——部署规范要求每次发布先写更新内容" >&2; exit 1
  fi
fi
```

`ALLOW_MISSING_RELEASE_NOTES` 是**留痕式后门**：存在，但必须显式打开、且日志一行可 grep；不进 `.env` 模板，不进文档主流程。

**verify.sh（④）**

```
[15] 发布说明：GET /access/api/release-notes → current.version == VERSION 且 slides ≥ 3
```

### 5.4 发布 SOP（`docs/RELEASE-PROCESS.md`）

```bash
# 1) 升版本（唯一事实源）
printf '0.2.1\n' > VERSION

# 2) 生成清单骨架（含 4 页示例结构与字数占位）
node scripts/release-notes-new.mjs 0.2.1

# 3) 截图/录屏 → releases/0.2.1/assets/，回填哈希
node scripts/release-notes-gate.mjs --hash

# 4) 门禁 + 全仓验证
bash deploy/release-notes-check.sh
pnpm -w run verify

# 5) 部署（既有序列，只是前面多了一步）
bash deploy/pre-restart-check.sh && bash deploy/backup-data.sh
docker compose build && docker compose up -d
bash deploy/verify.sh
```

规则三条：
- **内容变了就必须升版本**。同版本重发会让已读用户永远看不到新内容。
- **版本升了就必须有清单**，哪怕只有一页「修复若干问题」——空着不写才是不允许的。
- **rc 不发公告**：`announce:false`，弹窗不弹，但清单仍要通过门禁（内容留痕）。

## 9. 已知取舍

1. **图片走 HTTP 而不是随客户端 bundle**：bundle 会随版本增长且无法按需加载；资产走路由可长缓存、可懒加载，代价是多一个守卫面（已按白名单收紧）。
2. **截图用浅色**：与产品默认一致，深色用户会看到一块亮图。业界（Linear、Slack）同样如此。
3. **不提供永久退订**：本功能的价值来自"被看见"；退订等于把功能关掉。用户确实不想看时，「以后再看」成本只有一次点击。
4. **rc 不弹窗**：预发布面向内部，弹给终端用户是噪音；但清单照样要写，因为它是这一版的唯一用户语义记录。

## 10. 与既有规范的关系

- 前端铁律 1：不是独立页面；弹窗注册进原生浮层槽 `shell.overlay`，设置入口是 `settings.section` 分区 → 合规。
- 前端铁律 2：全部样式引用 `--et-*`，图标走 `@eterna/ui/icons`（需新增 `chevron-left` 一枚，其余复用 `check/close/folder/comment`）→ 待补一枚图标，不手写 SVG。
- 前端铁律 3：无资料字段合并保存问题；`no-store` 已明确；破坏性操作无。
- 多租户：新表在 DSH_HOME 语义下、路由面在 access、无跨租户读取 → 合 §1.1。

## 11. 决策

### 已定（2026-11-24 用户拍板）

| # | 事项 | 结论 | 落到实现 |
| --- | --- | --- | --- |
| D1 | 弹窗尺寸 | **880×720**，与设置弹窗同族；视口不足时四周留 24px | 原型 `:root` 的 `--wn-width/--wn-height` 即是；不新增尺寸例外 |
| D2 | 关闭语义 | **任何关闭都记已读**（×、Esc、遮罩、「以后再看」、「知道了」） | `release_notes_seen.via` 记原因；重看只走「设置 → 更新记录」 |
| D3 | 永久退订 | **不做** | 无退订开关、无 opt-out 字段；§2.2 的「不补课」与本节共同构成打扰边界 |
| D4 | 首版起点 | **下一个正式版开始公告**，不补 rc | `VERSION` 初值即下一正式版；`announce:false` 只用于 rc/热修清单留痕 |
| D5 | 截图 | **CI 自动化**，不手抠 | `scripts/release-shots.mjs`（真启动+Chrome+画布 webp）+ CI job `release-shots` 上产物 artifact；合规判定仍归 `release-notes-gate`（§3.3） |

D2 与 D3 同源：既然没有退订开关，「以后再看」若不记已读就会每次进入都弹，等于用一个更烦人的方式变相退订。
因此关闭即已读是 D3 的必要配套，不另开选项。

D5 的边界（防止把「自动化」吹成「无人值守」）：脚本自动出图，但**文案仍由人写**，且 CI 产物不会自动提交回仓库——
截图落库属于发布动作，按既有纪律单独确认。跨机器不比对像素，理由见 §3.3。
