# 47 · 知识底座 × 知识库融合开发计划

> 状态:已实施(2026-11-19,分支 `feat/knowledge-fusion`)。
> 起因:产品判定「知识库插件本质上就是知识底座的 wiki 方式的具体实现」——两套东西必须合成一个。

## 1. 改前事实(为什么必须融合)

| | `eterna-knowledge`(知识底座) | `eterna-knowledge-admin`(知识库) |
|---|---|---|
| 包 | `@eterna/glue/knowledge-plugin` | `@eterna/knowledge-admin` |
| 装载 | glue bundle 内 insert 行 | profile baked row(2026-11-19 转内置)或 bundle 安装(旧卷) |
| 工具 | 4 个 `knowledge_*` | `knowledge_admin` |
| UI | 无 | 侧栏「知识库」+ 七标签工作台 |
| 服务实例 | 自己的 `KnowledgeAccountRouter` + 池 | 自己的 `BackendPool` |
| 写入门禁 | `propose` 只落 pending | `saveDoc` 缺省 `publish=true`(直发) |
| 存储 | 逐字段同路径,但各开各的 SQLite 池 | 同左 |

后果:

1. 用户看到两个入口,不知道「以哪个为准」;
2. 同路径双池(WAL 下可共存,但重复索引/重复连接,检索结果口径分裂);
3. 管理面 `search` 里有一条**永远取不到**的平台 `@eterna/knowledge` 分支(死代码);
4. 写入语义分裂:面板「保存并提交」实际直接发布,而 Agent 只能提案,产品口径讲不清楚;
5. 知识库插件一换装载形态就消失(11-19 事故根因):bundle 与内置两套装载并存。

## 2. 拍板口径(2026-11-19)

1. **唯一宿主 = `@eterna/knowledge-admin`**;装载 id 保持 `eterna-knowledge`;显示名保持
   「知识底座」;删除 glue knowledge 插件。包名保留 `@eterna/knowledge-admin`(历史名,不在此批改名)。
2. **人工面板单篇保存直接发布;Agent 写入一律 pending**。Agent 工具移除 `review` 与 `publish`;
   只有 access 守卫铸出的真人 caller(`human:true`)能审批/直接发布。批量导入仍落提案。
3. **管理员默认全局库**:Agent 与面板都默认 `*`;面板新增账号切换器(全局/本人/各账号);
   普通账号只能看自己。
4. **客户端半边随融合一起修 v4**:令牌、圆角、字号、字重、响应式、图标全部清理,
   附深浅两主题 × 1440/900/390 截图。

## 4. 门禁矩阵

| 通道 | caller `human` | saveDoc | reviewProposal | 工具面 `review` |
|---|---|---|---|---|
| 浏览器面板(access 守卫) | `true` | `publish` 缺省 true → 直接发布 | 允许 | 不存在(工具面没有该 action) |
| Remote 网关(`LOCAL_CALLER`) | `false` | 恒 pending | `forbidden` | 返回 `forbidden` |
| Agent 工具(`routing.ts`) | `false` | `knowledge_propose` / `save` 恒 pending | `forbidden` | 返回 `forbidden` |

- `human` 只由 access 守卫铸出;服务面不信任调用方自觉。
- `#sanitize`:admin 空目标 → `*`;非 admin 空目标 → 本人;非 admin 指向他人 → `forbidden`。
- 会话 → caller 路由:`mode=auto`(缺省)/`per-account`/`global`;解析失败 fail-closed,
  绝不静默退回全局库。

## 6. 迁移(旧卷)

`docker/entrypoint.sh` 三件幂等动作:

1. profile `package.json` 的 `dsh.profile.bundles` 移除 `@eterna/knowledge-admin`;
2. 物化 patch 删除遗留 `- id: eterna-knowledge-admin` 块(缩进感知,同缩进 `- ` 兄弟行停);
3. `ln -sfn` 把旧 workspace 副本覆盖为 `/repo/packages/knowledge-admin`。

无重复 Loader source / 重复 provide 报错;baked row id 与旧 bundle 行 id 不同
(`eterna-knowledge` vs `eterna-knowledge-admin`),不会撞 id。

- **基线既有问题(与本融合无关)**:`scripts/build-market.mjs` 在 `origin/main` 上已因
  memory 新增跨包 import(`@eterna/evolve`/`@eterna/interact`/`@eterna/evals`/`@eterna/packctl`)
  无法自包含重建,`market/glue-bundle` 已在库版本陈旧。本批只做**手清 knowledge 件**

  不重新生成整包;market 重建需单独一批先解决 memory 的构建图。
