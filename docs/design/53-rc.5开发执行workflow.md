## 4. 派发协议（多会话/多 Agent）

每个工作包派发时必带五要素，缺一不收：

1. **输入**：49/50/51 的节号 + 上游 tag 文件路径（精确到 `git show <tag>:<path>`）；
2. **产出**：文件清单 + 验收命令（可复制执行）+ 证据路径；
3. **边界**：允许改的路径白名单；禁止改的路径（其它 lane 的热点、生产、上游）；
4. **完成定义**：命令退出码 + 断言条数 + 失败时回退方式；
5. **回报格式**：`files / commands / result(exit+摘要) / leftovers(RAID 条目)`。

派发顺序：L1 串行先行（全仓编译依赖它）→ L2/L3 并行 → L4/L5 并行（模板定稿后）
→ L6 随各 lane 落地同步补脚本 → P7 全量回归由主线统一执行。

## 5. 遗留处置（RAID）

**任何未完成、未验证、有疑问的点，一律登记，不许口头带走。**

登记字段：`id | 来源(用例/WP) | 现象 | 影响 | 级别(P0/P1/P2) | 方案 | 派发给谁 | 状态`。

处置六步：

1. **记录**：写进本文件 §9 遗留表 + `docs/dev/TODO.md` 当日记录；
2. **定位**：给出根因证据（命令输出/文件行号/上游路径），禁止“感觉”；
3. **方案**：≥1 个可执行方案，写明改动面与风险；P0 方案必须含回退；
4. **派发**：按 §4 五要素派给对应 lane；跨 lane 的拆单；
5. **复验**：用 51 对应用例复跑，证据归档；
6. **关闭**：状态改 `closed` 并附证据路径；P0 未关闭不得进 P7。

级别判定：跨租户/数据损坏/启动失败 = P0（立即停线）；功能主路径缺失 = P1；
体验/边界 = P2（可带已知问题发布，须产品签字）。**本轮目标：P0/P1 清零，
P2 只留 51 §12 已接受的开放项（T3/T5 等）。**

## 7. 交付

1. **PR**：`feat/dsh-rc5-merge` → `main`；描述含 49 §4 决策摘要、51 P0 结果表、
   已知风险（H7/H16）与回滚方式；附证据目录索引。
2. **合并**：CI 七层全绿 + 人工复核后合并（`git push` / 合并单独确认）。
3. **部署**：以**合并后 latest main**为源构建 `eterna-agent:<新 tag>`；
   `deploy/init-data-dirs.sh` + `$HOME/eterna-data/<instance>`；`-p agent-basis`；
   `verify.sh` + 登录/对话/文件/记忆/工作台冒烟。
4. **回滚**：旧镜像 tag + 冷备 `/data`；48 §7.6。
5. **发布说明**：rc.5 例外（upgrade-gate §7）、MCP HTTP 策略、H7/H16、terminal 限制。
