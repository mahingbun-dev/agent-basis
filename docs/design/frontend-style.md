# Eterna 前端风格规范（frontend-style v4「温润如玉」）

> 2026-11-19 起为仓库强制规范（见 AGENTS.md「前端与产品形态铁律」）。
> **违反 = 审查打回，不接受"下次再说"。**
>
> 取代 v3.2（Webflow）。v3.2 的工程纪律（令牌唯一、双主题、交互一致、可访问性、
> 无自建导航）**全部保留**；视觉基底、圆角体系、字重、叠层契约**全部替换**。
> 完整设计依据与实测：[42 号 v4 视觉体系](42-前端视觉体系v4-温润如玉.md)；
> 迁移工序：[45 号迁移开发计划](45-前端v4迁移开发计划.md)。
> 参考实现：`packages/ui/src/tokens.ts`、`packages/access/src/client/styles.ts`。

## 0. 一句话立场

**玉是暖的、层层相套的、含着光的。** 达成它靠三条可执行约束，不靠形容词：

1. 全阶带暖底（宣纸 `#f4f2ec`），纯白与纯黑都不出现。
2. **子圆角 = 父圆角 − 内边距**（同心弧），不允许任意圆角。
3. **把文字变成形状**：状态、过程、比例各有对应形状（§3）。

## 1. 铁律（十条，逐条可机器检查）

1. **令牌唯一**：颜色、字号、间距、圆角、阴影、动效只允许 `--et-*`；
   十六进制只允许出现在 `packages/ui/src/tokens.ts`。
2. **圆角走阶梯**：只允许 `var(--et-radius-*)`，底层值仅
   `8 / 12 / 16 / 22 / 28 / 36 / 9999`。**任何字面 px 圆角 = 打回。**
3. **同心弧强制**：嵌套容器的圆角必须满足 `子 = 父 − 内距`，按阶梯下取整
   （例：父 22、内距 8 → 子取 12）。见 §2.2。
4. **双主题**：应用内插件面必须经 `DSH_BRIDGE_CSS` 跟随产品壳；独立页用
   `WEBFLOW_TOKENS_CSS`。只出一套色 = 打回。
5. **骨架复用**：功能进 `settings.section` 等既有 slot；禁止自建导航/新入口
   （`/login` 是唯一例外）。
6. **叠层位置即语义**（v4 新增）：决策贴输入卡、toast 占顶部、通知进设置。
   三者不得同区。见 §4。
7. **文字预算**（v4 新增）：优先卡片/珠链/玉环/条带；段落 <= 3 行；
   一张卡标题 <= 12 字、说明 <= 40 字、动作 <= 2 个。见 §3。
8. **交互纪律**：资料类字段合并保存（脏检查 + 单按钮）；密码独立卡；
   变更请求防重复点击；破坏性操作两击确认，禁止原生 `confirm()/alert()`；
   HTML 响应 `no-store`。
9. **可访问性**：对比度正文 ≥4.5:1、UI 元件 ≥3:1；`:focus-visible`
   用 `0 0 0 3px accent/22%` + 边框转 accent；触控 ≥36px;语义标题不跳级；
   `prefers-reduced-motion` 全覆盖；状态必须"色 + 形 + 字"三重。
10. **响应式是契约不是补丁**（v4 强化）：见 §5，**位置规则在任何宽度下不变，
    只有形态收缩**。

## 2. 令牌

完整值与推导见 `packages/ui/src/tokens.ts`（唯一真值）。

### 2.1 色板（摘要）

| 角色 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 宣纸 `bg` | `#f4f2ec` | `#161917` | 页面底 |
| 玉面 `surface` | `#fbfaf6` | `#1e2320` | 卡片 |
| 凹槽 `surface-2` | `#efede5` | `#242a26` | 侧栏、分组 |
| 输入 `surface-3` | `#e6e3d9` | `#2b322d` | 输入底 |
| 墨 `fg` | `#1b1e1c` | `#eceee8` | 正文 |
| 黛青 `accent` | `#2b6272` | `#7fb2bd` | 强调、焦点、主操作 |
| 青玉 `jade` | `#3f7d6a` | `#6fae95` | 成功、完成态（图形专用） |
| 砂 `sand` | `#c2a179` | `#d8bb95` | 警告配套、次级强调 |
| 危 `danger` | `#a63d2e` | `#e08373` | 破坏、失败 |

**强调色预算：每屏可见 accent ≤ 2 处**（链接计 1 处，主按钮计 1 处）。

### 2.2 圆角阶梯与同心弧

```
xs 8 · sm 12 · md 16 · lg 22 · xl 28 · 2xl 36 · pill 9999
```

| 元素 | 圆角 |
| --- | --- |
| 输入、小控件、菜单项 | `sm` 12 |
| 卡片、工具卡、行卡 | `md` 16 |
| 决策卡、浮层菜单、输入框容器 | `lg` 22 |
| 弹窗 | `xl` 28 |
| 全高侧栏 / 大面板 | `2xl` 36 |
| 胶囊 chip、头像 | `pill` |

**同心弧算法**（强制）：`child = nearestStep(parent − padding)`，向下取整到阶梯。
反例（一律打回）：`padding:12px` 的卡里放 `radius:16px` 的子卡（应取 12 或 8）；
父 `lg` 内距 0 却给子 `xl`（应同 `lg`）。

### 2.3 材质

- `--et-bevel`：`inset 0 1px 0 rgba(255,255,255,.72)` + 1px 内描边。
  **仅强调卡**，每屏 ≤1 张。
- 阴影四级 `r1..r4`（暖底 rgba(38,42,36,·)）：行卡 `r1`、强调卡 `r2`、
  浮层与决策卡 `r3`、弹窗 `r4`。**禁止零偏移彩色光环**。
- **禁止**：`backdrop-filter`（唯一例外 = 弹窗遮罩 `blur(2px)`）、装饰性渐变、
  两段式 hero 渐变、玻璃拟态。

### 2.4 排版

- 标题宋体（`--et-font-display`），正文黑体（`--et-font-body`），等宽 `--et-font-mono`。
- 字阶：`micro 11 / caption 13 / body 15 / lead 20 / h3 24 / h2 32 / h1 40 / hero 64`。
  **middle 13 是 v4 新值**（v3 的 14 取消）。
- 行高：正文 `1.7`，紧凑 `1.35`。
- 字重**只有三档**：400 正文 / 500 强调 / 600 标题。**正文出现 500 = 打回**
  （v3 全站 500 是"模板感"最大来源）。
- 宋体标题每行 ≤ 20 字。

## 3. 信息转译五式（"少大段文字"的可执行形式）

| 式 | 触发 | 形态 | 约束 |
| --- | --- | --- | --- |
| 一 | 一段说明 | 卡片 | 标题 ≤12 字、说明 ≤40 字、动作 ≤2 |
| 二 | 执行过程 / 多步 | 珠链 | 每步 2–4 字，≤7 步，当前步有呼吸 |
| 三 | 比例 / 占用 / 预算 | 玉环 | 环心放数值，环本身表比例；不配进度条 |
| 四 | 趋势 / 序列 | 条带 | 单色 + 峰值一档加深；不用多色堆叠柱 |
| 五 | 状态 | 玉色阶 + 形 + 字 | 颜色不可独用，必须配形状或文字 |

**段落预算**：任何卡片内连续正文 ≤ 3 行；超出必须转译。
**动效预算**：常驻循环动画每屏 ≤ 2 处（仅"进行中"的呼吸与活线）；
其余只碰 `transform/opacity/color/box-shadow`；`prefers-reduced-motion` 下
移除位移与循环，只留 120ms 透明度。

## 4. 叠层与提示（位置即语义）

三个表面、三个固定席位，**永不同区**。完整规则见 42 号 §7a。

| 表面 | 席位 | 层级 | 生命周期 |
| --- | --- | --- | --- |
| 决策层（审批 / 提问） | 贴输入卡顶边向上浮出 | 200 | 至用户处理；超时按拒绝 |
| Toast | 顶部中央（`top:40px`） | 1500（走宿主原子则用其 1100） | 4 秒自散；带动作 6 秒 |
| 通知中心 | `settings.section` 分区 | — | 永续至标记已读 |

规则：

1. **决策层禁止用顶部浮层或全屏遮罩**。它是会话作用域的，只出现在所属会话。
2. 决策层遮住信息流时，必须把实测高度写进信息流 `padding-bottom`
   （`ResizeObserver`），并滚到底——否则被挡住的正是证据。
3. **不新建 toast 系统**：用 `@deepseek-ai/dsh-client-ui-primitives` 的 `Toast`
   原子或 `workspace.toast.content` 工厂席位。
4. 窄屏（<760）决策层**一次只呈 1 张**，其余排队并用切换条轮转。
5. `z-index` 只允许 `1 / 40 / 100 / 200 / 1000 / 1100 / 1500`
   （独立扩展页逃生舱单独白名单）。越级 = 打回。

## 5. 响应式契约（v4 强化，逐条可验）

**总则：位置规则不变，只有形态收缩。** 不允许"某个宽度下换一套布局逻辑"。

### 5.1 断点（唯一集合）

```
1100（三栏降两栏） · 760（侧栏隐藏、决策单卡） · 640（单列）
```

出现其他断点值（900/960/768…）= 打回。`760` 以下侧栏整体隐藏，由页面标题区
承担导航；表格必须 `overflow-x:auto`。

### 5.2 gutter

| 视口 | 页面内距 |
| --- | --- |
| ≥768 | 24 |
| <768 | 16 |

全高侧栏（贴窗口边）也必须有内距；`data-full-bleed` 是唯一的显式豁免标记，
且必须在视觉上真的贴边。

### 5.3 容器收缩规则

| 元素 | ≥1100 | 760–1100 | <760 |
| --- | --- | --- | --- |
| 设置弹窗 | 880×720 | 880×720（四周 ≥24） | 全屏，导航转横滚 |
| 决策卡 | `min(760, 100%)`，纵向 ≤2 | `min(680, 100%)` | 单卡贴满，内距 16 |
| Toast | `min(520, 100%-32)` | 同 | `100%-24`，字号 11 |
| 主面板 | 全宽 | 全宽 | 单列 |
| 三栏（工坊） | 320/1fr/320 | 220/1fr（右栏隐藏） | 单栏 |

### 5.4 验收方式（每个 PR 必附）

1. 1440 / 900 / 390 三视口截图，**深浅各一套**；
2. 断言 `scrollWidth === clientWidth`（无横向溢出）；
3. 边缘对齐：非豁免元素的左右边距 ≥ gutter（±1px）。
   > 实测配方见 42 号 §8b；本机无 playwright，用 `agent-browser` 的
   > `set viewport` + `eval` 探针，**且必须先 `close --all` 再 `set viewport`**
   > （会话已开时该命令静默失效，这是踩过的坑）。

## 6. 组件规则（摘要）

| 组件 | 规格 |
| --- | --- |
| 按钮 | 主：`accent-fill` 底 + `accent-on` 字 + `md` 圆角 + 高 40 + `r1`；次：透明 + 1px `border`；幽灵：无边框 `muted` 字；破坏：danger 描边 30% + danger 字 + 两击确认 |
| 输入 | `surface-3` 底、1px `border`、`sm` 圆角、高 40；聚焦边框转 accent + 3px 光环 + 轻微内阴影 |
| 卡片 | 一级 `surface`+`border-soft`+`r1`+`lg`+内距 20；强调 +`bevel`+`r2`（每屏 ≤1）；凹槽 `surface-2` 无边框无阴影 `md`；行卡 高≥56 `md` 悬停 `r1→r2` |
| 表格 | 表头 12px `muted` + 500、单元格 13px、行高 ≥48、仅横向 `border-soft`、数字 tabular；**行不得有圆角** |
| 弹窗 | `xl` 圆角、`r4`、遮罩 `--et-scrim` + `blur(2px)`、内距 24 |
| 浮层菜单 | `lg` 圆角、`r3`、内距 6、条目高 **40**、分隔 1px 且左右内缩 12 |
| 图标 | `@eterna/ui/icons`（React）或 `icon-data`（服务端字符串）；24 网格、**1.6px** 描边、圆头、`currentColor`；**禁止 emoji 功能图标、禁止圆形彩色底图标阵列、禁止上游图标与一次性手写 SVG** |
| 徽标 | `pill`、高 28、内距 6×12、12px（`--et-text-meta`）；状态色必须配文字 |

### 6.1 共享基础件的作用域（生产事故沉淀，2026-11-19）

`@eterna/ui` 的 `COMPONENT_CSS`（`.et-btn` / `.et-input` / `.et-card` / `.et-ring` /
`.et-beads` / `.et-strip` / `.et-badge` / `.et-decision-*`）全部限定在
**`[data-eterna-ui]` 作用域**内。这个标识由 `injectDesignTokens({bridge:true})`
落在 `body` 上，插件**不需要也不应该**自己加。

> 为什么写进规范：改造期间发现全仓**没有任何一处**设置该属性，
> 于是这些样式在真实产品里一条都不生效——工作台指标卡的玉环渲染成
> SVG 默认黑盘，按钮/决策卡零样式。而当时的验收探针页手动加了该属性，
> 于是「探针绿、生产坏」，属于假绿验证。
>
> 护栏：`packages/ui/tests/contract.spec.ts` 现在断言
> (a) 桥接模式必须落标识且 disposer 必须移除；(b) 标识只在应用内设置；
> (c) COMPONENT_CSS 每条规则都必须带 `[data-eterna-ui]` 前缀。

自建样式的插件遵守两条：

1. 根节点用 `data-eterna-access-root` 这类**自己的**命名空间锚点（本插件私有）；
2. 想复用共享基础件（按钮/卡片/玉环…）时，直接加 `.et-*` 类即可，
   **不要再给元素加 `data-eterna-ui`**——它已经在 `body` 上。

### 6.2 宿主桥接的三层覆盖（生产事故沉淀，2026-11-19）

暖玉要覆盖的是宿主 **三个** 令牌层，缺一层就有肉眼可见的破面。三层都不是
"可选优化"，是必需项：

| 层 | 谁在读 | 漏掉的后果（实测） |
| --- | --- | --- |
| `--dsw-alias-*`（114 个） | 宿主壳（侧栏/输入区/气泡/按钮） | 发送按钮停在 `#4176e6` 电光蓝 |
| `--dsw-static-*`（82 个） | 宿主里直接取静态令牌的地方 | 别名漏网时漏出冷白/电光蓝 |
| `--dsw-specific-*`（10 个） | 侧栏底、气泡、菜单、登录输入 | **整个侧栏**停在宿主亮底 |

三条硬约束：

1. **选择器必须 `html body`**，不能用 `body`。宿主主题插件同样在 `body` 上定义
   这批别名，且样式表在插件 bundle **之后**注入——同权重后写胜出，暖玉被冲回
   `--dsw-static-neutral-bluish-*` 的冷白。`html body` 是 (0,0,2) > (0,0,1)。
2. **静态色板只映射一次，深浅共用**。宿主的 `--dsw-static-*` 在浅色块与
   `body[data-ds-dark-theme]` 块里**取值完全相同**——它是固定色板，主题差异
   全在语义层（如 `sidebar-fill` 浅色指 `bluish-50`、深色指 `bluish-900`）。
   在深色块里再写一套"反向阶梯"会把 `bluish-900`（深色侧栏底）翻成亮色，
   深色界面直接塌一半。深色需要单独覆盖的是 `--dsw-alias-*` 与 `--dsw-specific-*`。
3. **`--dsw-specific-*` 深浅各配一套**，且深色侧栏必须比页面底**更沉**
   （`#161917` < `#1d211f`），不是更亮。

> 护栏：`packages/ui/tests/contract.spec.ts` 现在断言
> (a) 宿主实际使用的别名全覆盖（含主题插件 `client.js` 这一路——一批别名
> 定义在 JS 里而非 CSS 资产，只扫 CSS 会漏）；(b) 静态色板覆盖齐全且不含
> 纯白/纯黑/电光蓝；(c) 静态映射块恰好一个且落在 `html body`；
> (d) `--dsw-specific-*` 深浅两侧全覆盖。

> 教训：前两轮我按"补别名"修，每次上线后都能再找到一处残留。把静态色板整层
> 关掉之后，宿主新增别名也不会漏出冷白。**先找指针指向的底层，再谈逐条打补丁。**

## 8. 与 v3 的关系（迁移期约定）

v3.2 仍然有效到 **45 号计划 P0 合入**为止；P0 之后本文件是唯一视觉真值，
`frontend-style.md` 中不得再出现 v3 令牌表（避免两套真值）。
迁移期间新代码一律按 v4 写，老代码在 45 号 P3 逐包重排时对齐。
