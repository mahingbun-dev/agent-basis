## 2. 迁移原则

1. **分层落地，不并行改色。** 先令牌（一次性全站生效），再共享件，再逐面重排。
   倒过来做会得到"新圆角 + 旧密度"的四不像。
2. **机械项交给 lint，不靠人眼。** 现有 `scripts/lint-ui-tokens.mjs` 已管字号阶梯、
   断点集合、字面色值、未定义令牌；本轮给它加三组规则（§4.1），不新增工具。
3. **每阶段可独立验收、可独立回滚。** 令牌阶段回滚 = 还原 `tokens.ts`；共享件阶段
   回滚 = 删组件；页面阶段按包回滚。
4. **不改信息架构、不改文案、不改交互语义。** 本轮只换皮、换布局密度、换叠层契约
   （见 42 号 §1.1「必须保留」）。

## 4. 护栏（防止迁移后回潮）

### 4.1 已落地的三组规则（本次提交，已通过实测）

`scripts/lint-ui-tokens.mjs` 新增并已生效：

1. **圆角阶梯**：`border-radius` / `borderRadius` 只允许 `var(--et-radius-*)`
   与 8/12/16/22/28/36/9999（0 与 50% 属形状，放开）。
2. **层级表**：`z-index ≤ 40` 归组件局部层叠（下拉/菜单，合法）；
   `> 40` 必须精确取自 100/200/1000/1100/1500。
3. **债务清单** `LADDER_DEBT`：现存越级项登记在案（4 项），**不阻塞 CI**，
   但新增越级一律打回；条目清完后清单归零、规则自动升为硬门禁；
   条目已失效（源码里不再有此越级）会反向报错，强制删除过期条目。

### 4.1a 扫描面从白名单改为全覆盖（2026-11-19 增量扫描的根因修复）

**这是本轮最重要的护栏修复。** 原 `SCAN_DIRS` 是手写 11 个目录的白名单——
新包默认不受检查。`knowledge-admin` 正是因此带病入库（992 行、23 处字面色值、
9 个上游不存在的令牌名）。

改为 `packages/*/src` 全覆盖 + `EXEMPT_DIRS` 显式豁免（豁免须注明理由）：

| | 修复前 | 修复后 |
| --- | --- | --- |
| 扫描目录 | 11（手写白名单） | **16**（全覆盖 + 豁免） |
| 扫描文件 | 185 | **249** |
| 新包行为 | **默认放行** | 默认纳入检查 |

**回归验证**（本轮实测，把 `knowledge-admin` 真的拷进工作区跑）：

| 动作 | 结果 |
| --- | --- |
| 仅改扫描目录（未收 `.js`） | **仍通过** —— 暴露第二道断点 |
| 恢复 `.js` 到 `walk()` 的文件过滤 | **报出 23 项，全部命中 knowledge-admin，无误伤其他包** |
| 移出该包后重跑 | 通过，`16 个目录 249 个文件` |

**两道断点都必须补，缺一不可**：

1. `SCAN_DIRS` 是手写白名单 → 新目录根本不进扫描面；
2. `walk()` 只收 `.ts/.tsx/.html` → **`.js` 客户端半边（`knowledge-admin` 正是纯 `.js`
   手写 `h()`）即便进了扫描面，也会被整体跳过**。

第二点尤其隐蔽：只改第一处，扫描面"看起来"从 11 扩到 16（数字变好看了），
新包却依旧全绿——**纸面推演会以为已经修好，只有真拷进工作区跑才暴露**。
