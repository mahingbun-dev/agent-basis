# 14 - 开发总排期与工作流执行(单流连续,不分阶段)

> 2026-11-03 定稿。用户要求:**所有开发项经一次持续运行的 workflow 完成开发→验证→产出,不分阶段交接,防丢进度**。本文是总控:节奏、任务分解、依赖、验证门、进度持久化机制。每个功能的完整设计见 08/09/10/11/12/13 号文档,workflow 是它们的可执行形态。

## 1. 执行形态:一条 workflow,五个相位,14 个任务

```
相位1 搭建工程地基
  T0 agent-basis monorepo 脚手架(pnpm/tsconfig/vitest/oxlint/PROGRESS.md/git init)
相位2 开发治理插件(其他插件的安全地基)
  T1 dsh-governance
相位3 并行开发七个核心插件
  T2 dsh-memory  T3 dsh-interact  T4 dsh-evals(CLI)  T5 packctl(CLI)
  T8 dsh-knowledge  T9 dsh-observe  T12 dsh-cache-guard
相位4 金集与领域包、平台对接、通道与自进化引擎
  T6 活动策划 golden set + @event/pack →(链式)T7 ai-evo 平台对接
  T10 dsh-evolve   T11 dsh-channels   T13 收尾插件(egress 完整/reviewer/tenant)
相位5 总装验收并交付开发报告
  T14 全局 verify + packctl lint + dsh-evals replay 20 条 + DEV-REPORT + 回写 Obsidian(15 号)
```

## 3. 进度持久化(三重,防丢)

1. **workflow 运行日志本身**(run journal,可 resume/amend,缓存按子代理名匹配);
2. **agent-basis/PROGRESS.md + git 提交**(每任务一提交,任意时刻可断点续传);
3. **看板 artifact**(实时 14 张卡片:待开发/开发中/完成/受阻)+ 完成/受阻即时 report(即使运行失败也已送达)。

## 4. 韧性规则

- 单任务验证失败:同上下文修复循环(≤3 轮),仍失败→标"受阻"**不拖死全局**,下游按接口 mock 继续并在 blockers 注明;
- 依赖 DSH 运行时的真连(acp 驱动/WeKnora/微信/ai-evo 无 Key):实现到位+接口测试,**真连验证列入 notCovered**,不伪造;
- 子代理诚实条款:门不可能过/指令矛盾→升级提问,禁止绕过或伪造测试结果。
