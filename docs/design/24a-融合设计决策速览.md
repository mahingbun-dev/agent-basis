# 24a - 融合设计决策速览（一页纸）

> 配套：`24-主动工作体系融合设计-任务内核与chat-demo范式.md`（完整论证与证据）· `25-业界架构对照与缺陷清单.md`（外部依据：业界四派分歧、MAST 14 种失败模式、九个卡点）
> 用途：给决策者快速过一遍「做什么、不做什么、付出什么、得到什么」

---

## 一句话

**把 DeepSeek 开源的「任务内核」移植成本仓的 L1 插件 `packages/tasks`，用 chat-demo 的交互范式做表面，让 EternaAgent 从「聊天助手」变成「能接活的同事团队」。**

---

## 三个判断

| # | 判断 | 依据 |
|---|---|---|
| **1** | **不需要网关桥接** | superagent 与本仓同宿主（DSH），其 `src/core/` 零 I/O、零外部依赖、Ports 解耦 → 可直接移植 |
| **2** | **不装它的 bundle** | 第二个 bundle 会有 plugin id / stateDir / panel 路由三重冲突 → **只取 core** |
| **3** | **chat-demo 只取范式** | 它是纯静态后端无关的前端；本仓会话归属上游 DSH → 取 SSE/块归并/投影/分支四套做法，不取其存储 |

---

## 现状缺什么（6 条，皆有证据）

| 缺口 | 一句话 |
|---|---|
| G1 纯被动 | 全仓无 Trigger/Ticket/Mandate 概念，一切由用户消息驱动 turn |
| G2 审批半接线 | `escalate`/`cooling_period`/`double_confirm` 只有声明，无运行时消费者 |
| G3 授权断层 | 只有全局规则 + 单次 allowed-once，缺任务级授权；规则无版本 |
| G4 channels 未挂 | 绑定/令牌/卡片就绪但生产未装配；只能续接「会话」不能续接「工作」 |
| G5 会话即一切 | 一个会话承担对话+工作+历史，无独立工作对象 |
| G6 无编排 | 无主/worker 分工、无并发槽、无扇出 |

## 做什么（四阶段）

| 阶段 | 周期 | 交付 | 风险 |
|---|---|---|---|
| **P0 还债** | 1 周 | Attention 台账 + escalate 接 channels + 冷静期/双确认接线 | **零风险**，独立可交付 |
| **P1 内核** | 2–4 周 | `packages/tasks`（Engine + Mandate + Ticket + Subscription + Outbox/Effects），先只做 explicit 委托 | 中（移植质量控制） |
| **P2 表面** | 2 周 | 任务侧栏 + 报告时间线 + Attention 卡片 + 多 Assignment 分支 | 低（走已有 slots 扩展点） |
| **P3 差异化** | 持续 | `inferred` 观察模式 → observe/evolve 闭环 + `ticket.ended` 记忆钩子 | 中（需试点验证） |

### P1 的六条实施契约（缺一条就会继承 superagent 的已知缺陷，详见 25 号 §5）

| # | 契约 | 一句话 |
|---|---|---|
| R1 | 主 Session 预算守卫 | 多智能体 15× token；superagent 全仓**无主动成本上限** |
| R2 | `ready` 必须过门禁 | worker 自述不作数；MAST 头号失败类是"无验证/验证不正确" |
| R3 | 委派四要素硬约束 | objective / output format / tool guidance / task boundaries，缺则拒 |
| R4 | worker 输出落文件 | 避免跨 worker 的"telephone"信息失真 |
| R5 | Attention 显式化 | 可映射 A2A `input-required`，但保留"追认可恢复结案工单" |
| R6 | 不重写持久执行引擎 | 评估 DSH 宿主能力；别从零手写 mini-Temporal |

## 得到什么（三个不可替代）

1. **任务闭环 × 受控自进化**——两个官方仓库都没有，只有本仓能做：报告失败 → 信号表 → skill delta → G0/G1/G2 门禁 → 下次更准。
2. **可治理的自动化**——每次自主都绑一份可解释授权（Mandate + 策略版本）、每次越界撞不可翻案红线（deny-wins）、每个动作落可追溯工单。
3. **人的动作从全程盯着降到 4 次**——发起 / 答一问 / 验收 / 可能的退回。

---

## 不做什么

- ❌ 不装 superagent bundle
- ❌ 不照搬 git worktree（那是编码场景）
- ❌ 不引入 chat-demo 的存储与 BYOK 模型
- ❌ 不新增独立页面（严守 AGENTS.md，走 slots）
- ❌ 不做无规则的主动行为（先 dry-run）

## 待拍板（8 项，详见 24 文 §9）

**优先级最高三项**：
1. **P0 是否先做**？（零风险还债 vs 直接进 P1 省一次重构）
2. **规则版本化会不会伤热改**？（建议：版本号 = 文件内容 hash，热改即新版本）
3. **realm 进内核模型还是外层过滤**？（前者不变量硬，后者改动小）

其余：worker 权限模型、Source 边界、首批场景选型、chat-demo 未来定位、是否贡献上游。
