## 3. M-M1 实现规格

### T1 数据层迁移(`entity-store.ts` + 新 `domain.ts`)

**DDL(在 `openDatabase` 迁移段执行;`PRAGMA table_info(memory_entity)` 检测缺列才 ADD,幂等)**:

```sql
ALTER TABLE memory_entity ADD COLUMN kind TEXT NOT NULL DEFAULT 'semantic';        -- episodic|semantic|procedural
ALTER TABLE memory_entity ADD COLUMN scope TEXT NOT NULL DEFAULT 'domain';         -- user|domain|legacy-org
ALTER TABLE memory_entity ADD COLUMN domain_key TEXT;
ALTER TABLE memory_entity ADD COLUMN review_state TEXT NOT NULL DEFAULT 'approved';
ALTER TABLE memory_entity ADD COLUMN origin_session_id TEXT;
ALTER TABLE memory_entity ADD COLUMN origin_turn_ref TEXT;
ALTER TABLE memory_entity ADD COLUMN source TEXT NOT NULL DEFAULT 'agent';         -- explicit|agent|consolidation|compaction
ALTER TABLE memory_entity ADD COLUMN last_used_at INTEGER;
ALTER TABLE memory_entity ADD COLUMN use_count INTEGER NOT NULL DEFAULT 0;
CREATE INDEX IF NOT EXISTS memory_entity_scope_live ON memory_entity(scope, domain_key, invalid_at);
CREATE INDEX IF NOT EXISTS memory_entity_review ON memory_entity(review_state, invalid_at);

CREATE TABLE IF NOT EXISTS domain_registry (
  domain_key TEXT PRIMARY KEY,          -- kebab-case,≤64
  label TEXT NOT NULL,                  -- 展示名(中文)
  source TEXT NOT NULL,                 -- workspace|taxonomy|free
  hit_sessions INTEGER NOT NULL DEFAULT 0,   -- 注册前命中计数(≥3 才转正)
  registered INTEGER,                   -- 转正时间;NULL=候选中
  session_count INTEGER NOT NULL DEFAULT 0,
  memory_count INTEGER NOT NULL DEFAULT 0,
  last_used_at INTEGER, created_at INTEGER NOT NULL
);
```

**存量迁移(同事务,一次性)**:subject 前缀推断——`user:*` → `scope='user'`(subject 保持原值不动,检索按 scope 列);`project:*` → `scope='domain', domain_key=<原名>, subject='domain:<原名>'`;`org:*` → `scope='legacy-org'`(不删,所有检索/索引默认排除);无前缀 → `scope='domain', domain_key='default'`。

**新表落点**:新建 `packages/memory/src/domain.ts` 导出 `DomainRegistryStore`:`ensureWorkspaceDomain(key,label)` / `recordHit(candidateKey)`(候选计数,≥`minSessionsForNewDomain=3` 转正)/ `resolve(domainKey)` / `list(onlyRegistered)` / `touchUsed(domainKey)`。

**接口扩展**:`EntityRecord` 增上述字段;`EntityWriteInput` 增 `kind?/scope?/domainKey?/reviewState?/originSessionId?/originTurnRef?/source?`;live 唯一性约束不变(仍 (subject,key))。

### T2 工具层(`tools.ts` / `memory.ts`)

1. **provenance 盖章**:`MemoryHost` 增可选 `sessionContext(): { sessionId, turnRef? } | undefined`;glue 层从 dsh 会话面取值注入(⚠️S-5 核实 exec/ctx 取法);`memory_write` execute 内强制覆盖 `origin_session_id/origin_turn_ref`——**模型传参一律忽略**(不信任模型手写,ZCode 同款)。工具参数**不新增** provenance 字段。
2. **新参数**:`memory_write` 增 `kind: 'semantic'|'episodic'|'procedural'`(必填,description 给判定口径)与 `explicit?: boolean`(模型判定用户显式"记住"时 true);`memory_search` 增 `scope?: 'user'|'domain'`、`domain_key?`(过滤发生在相似度之前,Zep scoped retrieval)。
3. **subject 收敛**:description 改为"主体由系统管理:用户画像层用 `user`;功能域用 `domain:<域键>`;不需要也无法写 org(已禁用)"。
4. **四操作决策**(`writeEntity` 内,返回值增 `decision: 'add'|'update'|'noop'` 字段):同 (subject,key) 已有 live 行 → UPDATE(顶替,既有语义);不同 key 但同 scope+kind 内容相似度超阈值(首版:多词重叠 ≥60%,不引入嵌入)→ **强制走 UPDATE 路径**(把 content 合并写入既有 key)并在返回中给出被更新的 key;否则 ADD。NOOP:内容与既有行几乎一致(重叠 ≥90%)→ 拒绝写入返回 `{ok:true, decision:'noop', existing_key}`。
5. **review_state 规则**(写入口统一判定,非模型参数):`explicit=true` → approved;否则 `scope='user'` 或 `kind ∈ {semantic,procedural}` → **pending**;`scope='domain' 且 kind='episodic'` → approved(08 §5.4 静默档)。`source='compaction'` 强制 pending(留给 T6 写入)。
6. **检索过滤**:`search()` 与 `buildIndex()` 默认 `review_state='approved' AND invalid_at IS NULL AND scope != 'legacy-org'`;管理面读取走新 API `listForReview(state)`(不经模型工具,走 SRC 网关)。
7. **`Memory` 接口增**:`review(id, 'approved'|'rejected')`(rejected=打 invalid_at 软失效,不物理删)、`touch(ids)`(命中强化:`use_count+1, last_used_at=now`)、`listForReview(state, limit?)`、`supersede(id)`(Gm1 软失效入口)。

### T3 读取层(`index-builder.ts`)

1. **分预算**:`MemoryIndexOptions` 增 `portrait?: string`(画像摘要文本,≤150 token)、`domainKey?`(当前域);`buildEntityIndex` 输出结构改为 `画像区(若有)+ 域索引区(scope='domain' AND domain_key=当前域,≤250 token)+ 全局兜底区(剩余预算,user 层优先)+ footer`。**无域上下文时行为与现在一致**(向后兼容,单测钉住)。
2. **排序**:live 记录按 `confidence × 2^(−ageDays/90) + 0.1 × min(use_count,10)/10` 降序;90 为 `halfLifeDays`(config 可改)。
3. **时效尾标**:`updated_at` 距今 >14 天的索引行与 search 命中,summary 追加 `(N 天未验证)`,N=`floor(ageDays)`。
4. **召回前缀**:search 返回的 hits 组装进模型上下文时(present 逻辑在 tools render)附一行前缀:"检索结果为时点观察,引用前先验证仍然成立"(登记进提示词条目,见 T5)。

### T4 画像 v0(新 `portrait.ts`)

- 纯函数 `buildPortrait(records: EntityRecord[]): string`:聚合 `scope='user'` 且 approved 的 semantic 记忆 → Markdown,frontmatter `{version, generated_at, source_memory_ids[]}`;分节:工作习惯/风格偏好/协作要求/工作区索引(domain_registry 投影)。单节上限 10 条,超出按排序截断并在节尾注明。
- 写文件 `$DSH_HOME 语义下 workspace 的 .eterna/portrait.md`(与 sqlite 同目录,tenant-scan 覆盖)。
- M-M1 交付形态:导出函数 + `packages/memory/scripts/gen-portlot.mjs`(node 直跑,读库生成)——**无 UI、无定时**;定时与纠正入口在 M-M3。
- 索引消费:T3 的 `portrait` 参数由 glue 在装配时读 `portrait.md` 缓存(不存在则省略该区)。

### T5 合规件

- **tenant-scan**:`packctl` 增规则——`eterna-memory` 插件配置解析出的 dbPath/portrait 路径必须前缀匹配 `$DSH_HOME/workspaces/<账号>/`(或测试 profile 的隔离目录);违例即 CI 红。

## 4. M-M2 实现规格(写入管线)

### T6 整固 job 骨架(新 `consolidation.ts` + glue 挂载)

```
事件触发(⚠️S-1:dsh 会话/turn 结束事件的准确名称与负载,以 04 号笔记 §3 + node_modules 实测定稿)
  └─ consolidateOnSessionEnd(sessionRef)
       ├─ 门控(顺序固定,任一 skip 即推进游标):
       │   1. 会话段内存在 memory_write 调用 → skip(direct-write 防双写;工具调用记录可从 session log 扫,⚠️S-1)
       │   2. 无 ≥3 词独立用户文本 → skip(no-user-prose)
       │   3. 单轮跳过标记(本会话触发过凭据护栏/红线审批 → skip;来源 governance/audit 事件,⚠️S-1)
       ├─ 调度:单 running + 单 latest-pending(覆盖合并,无 FIFO;照抄 zcode extraction scheduler 语义,纯 TS 实现约 80 行)
       ├─ 游标:新表 consolidation_cursor(session_id 主键, done_at)——云端按会话粒度,不做消息级 cursor(比 zcode 简化,理由:会话即租户工作单元;rewind 场景本产品无此功能面)
       └─ 快照冻结:调度时快照 session log 路径+会话元数据,消费时不重查
```

- session close:先 abort 在跑整固再释放(glue disposer 内);60s drain 上界。
- 挂载:`memory-plugin.ts` 增 `config.consolidation = { enabled: true, trigger: 'session-end' }`;M-M2 不接 schedule(留 M-M3 重量任务用,⚠️S-4)。

### T7 提取执行

- **不用子代理**(M2 是 sqlite 非文件系统,受限工具面收益低;LLM 直调):`ctx.llm`(⚠️S-4 核实 glue 层 llm seam 取法,compaction `summarizer.ts` 已有先例 `ctx.llm.stream()` 缓存复用式调用,照抄其调用形态)以 curator 角色(默认 Flash,config 可改)跑冻结 prompt。
- 冻结 prompt:`packages/memory/tests/fixtures/extraction-prompt.md`(语义对齐 ZCode:只用最近会话内容/禁止 grep 验证/附现有记忆 manifest 要求查重/“没什么可记输出 Nothing to save”/显式记住-忘记立即执行);输出结构化提案 `[{op:add|update|forget, scope, kind, domain_key?, key, content, summary?, confidence?}]`。
- 提案落库走 `writeEntity`(带 `source='consolidation'`,review_state 按既有规则;compaction 摘要来源的提案 `source='compaction'` → 强制 pending)。

### T8 Gm0/Gm1

- **Gm0**(写入口同步,T2 已含):PII/长度(单条 content ≤2000 字)/单域 live 上限(perDomainLimit=200,超限拒绝并提示整固)/查重强制 UPDATE/NOOP。
- **Gm1**(整固 job 内,提案入库前):对每条 `add` 提案,取同 scope+kind 的 live 行做多词重叠;重叠 30–90% 区间 → 一次 LLM 矛盾判定调用(同 Flash):矛盾 → 新提案入库 + `supersede(旧行)`;互补 → 合并 UPDATE;无关 → 照 ADD。**与 AGENTS.md/NOTES 对账不在 M-M2**(M-M3 重量 Dream 引入 CONFLICT-FLAG)。

### T9 审批闭环

1. `Memory.review(id, state)`(T2 已建)。
2. 卡片:pending 产生时组 `ApprovalCardInput`(复用 `packages/interact/src/card.ts` 类型:标题"从本次会话学到…"、Why=出处会话摘要、Action=记住/跳过)——**送达链路 ⚠️S-2**(interact 卡片如何进 `conversation.approval.card`,沿 presets/ask 的现成通道;若通道需要宿主登记,照 compaction SRC 宿主层挂载先例)。
3. 队列 UI(M-M2 最小版):panel `snapshot` 增 `pendingCount` + 面板审批列表(批/拒按钮,两击确认拒绝);完整体验 M-M3。
4. 账本:每次整固的提案/门控/审批结果写一行 JSONL 审计(`$DSH_HOME 语义 workspace 下 .eterna/memory-audit.jsonl`;evolve ledger 挂载后切换,键位对齐)。

### M-M2 测试与验收

## 5. M-M3 实现规格(域整固 + 画像自动化 + 前端)

### T10 域检测与注册

- 会话启动(或首条用户消息后):`resolveDomain({ workspaceName, firstUserMessage, registry })`——**先归并**:LLM(Flash,冻结 prompt)从 `domain_registry` 已注册域中选(可空);无匹配 → 候选键(kebab-case)`recordHit`,**≥3 独立会话才转正**(Q2);workspace 显式域跳过打标直接注册。
- glue 把 `domainKey` 注入索引上下文(T3 参数);会话域归属写入 episodic 记录 provenance。
- 验收指标:人工标注 30 个会话样本,归并+注册准确率 ≥80%(进 T13 采集)。

### T11 双频次整固(Dream 四阶段)

- **轻量(会话尾,M-M2 已建)**:扩为"域打标落库 + episodic 摘要落域(kind=episodic, confidence=0.5, source=consolidation)"。
- **重量(周期,⚠️S-4 schedule seam)**:默认每日;四阶段——
  1. Orient:盘点 user 层+各域 live 记忆与索引规模;
  2. Gather:读窗口期内 episodic + evolve `evolve_signal`(若 evolve 已挂载;未挂载则只读 episodic);**窄读不全量**;
  3. Consolidate:① 域内晋升:同 (模式,根因) 聚类 ≥2(复用 `evolve/src/reflector.ts` 的 `clusterSignals`)→ curator 起 semantic/procedural 提案 → 审批卡片(Q3 全审);② 稳定偏好 → user 层提案(审批卡片);③ 矛盾对账扩展到 NOTES/AGENTS.md(冲突 → CONFLICT-FLAG:记 `conflict_flag` 列/复用 summary 前缀,并列入周报,不改指令文件);④ 相对日期转绝对;⑤ 删除被证伪事实(提案级);
  4. Prune:episodic TTL 30 天淘汰、perDomainLimit 挤出、半衰期降权复核、索引裁剪、**画像再生成**(T4 函数复用,写 portrait.md 并 bump version)。
- 画像再生成条件:user 层 approved 记忆数变化 ≥1 或距上次 ≥24h。
- 周报(轻量文本,channels 推送可后置):晋升/淘汰/CONFLICT-FLAG/画像变更摘要——M-M3 只落 panel 展示。
