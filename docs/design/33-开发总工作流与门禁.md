三条关系律（32 号 §1）：

1. **工作流是持续并行的施工线**，里程碑是纵切演示点——M1–M3 不依赖合拢、可独立演示维持动量；
2. **双形态是发布外壳不是代码分叉**——独立性表达在挂载面、发布流、数据卷上（31 号 §0）；Tier 规则 + 双 boot 门禁使单干线安全（两题互锁，32 号 §7）；
3. **上线节奏由运行时 policy 控制**（explicit-only 起步 / `inferred` 观察模式 / 误报率达标才放量），不是代码阶段（32 号 §5）——发布时功能全部就绪，放开节奏由策略控制。

原 24 号 §6 的 P0–P3 阶段划分已被 32 号取代（A3"做 P0"由"P0 溶解进工作流"取代）：Attention 台账→WS-A、escalate 接 channels→WS-E、冷静期/双确认→WS-E、原 P2 表面→WS-D、原 P3 观察模式/evolve 闭环→WS-A/WS-E 最终态功能（32 号 §3）。

## 2. 门禁可验收性规则

每条门禁必须落为以下三形态之一，否则不得进入本体系、不得进 CI（登记规约见 §2.4）。

### 2.1 三类型定义与判定

| 类型 | 标记 | 判定规则 | 本文档中的例子 |
|---|---|---|---|
| **命令** | 【C】 | 以**退出码**裁决：0=通过，非 0=失败；`dsh-evals` 特例 0/1/2 三态（1=质量不达标走回滚、2=基础设施错误修好重跑，不计入质量裁决） | G0-1～G0-6、G1 全部、G4-1/4/5/6/7 |
| **测试** | 【T】 | 以**测试文件 + 断言**裁决：vitest（`*.spec.ts`）用例全绿；**断言计数 enforcement 待建**（脚本 `--count` 输出 + 基线文件 `docs/baselines/*.count`，见 G2-F1——当前 t7 四脚本实测计数 30/92/130/18 无输出机制，删断言只会更绿）；enforcement 落地前判据 = 退出码 0；验收口径看工具输出 JSON 特征字段或面板计数，禁全页文本子串断言（用户消息回显会污染） | G2 各表的 spec 条目 |

### 2.4 新增门禁登记规约

新门禁进入本体系前必须：① 归入 G0–G4 某层并编号；② 声明类型（C/T/A 三选一）；③ 给出可执行命令或测试文件路径或产物路径**及其比对方式**；④ 标注出处文档。四项缺一即拒绝登记——与 packctl prompt-scan 白名单"每条必须写 reason"同款纪律（`docs/PLUGIN-AUTHORING.md:64`）。
